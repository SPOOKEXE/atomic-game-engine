# Particle 3D native camera profile

The pinned source is Pixel Composer commit `b69eca232217360cf1502ef0223523d818606652`. The native particle vertex adapter follows `datafiles/Shaders/3dInstance/3dParticleVS.hlsl` and `CommonInstanceVS.hlsl`. This is an explicit native profile, not evidence of licensed desktop GPU parity.

`MeshData3D.ParticleInstanced` distinguishes particle instances from ordinary instances, including an empty particle system. Particle meshes must be instanced and have one separate `ParticleRecord3D` for each transform. Ordinary meshes must have no particle records. The record preserves all sixteen finite f32 words: active, mesh index, maximum/current life, render flags, three reserved words, floating RGBA and velocity with its reserved fourth word. Transform RGB lanes are not particle colour. Unknown flag bits remain stored; the shader consumes billboard bit zero only. Life and velocity remain metadata and do not alter the vertex shader.

`SourceParticle3DVertex.hpp` exposes device-free preparation to the camera adapter. The source performs billboard orientation, object position transform, Euler rotation, up-normal orientation, instance scale and instance translation in that order. Billboard rotates both position and normal. Object transform, up-normal orientation and scale affect only position. Instance Euler rotations are authored degrees and the source matrix is applied directly; the ordinary instancer helper is not interchangeable. Normals remain unnormalized at this cut point. The source look-at helper uses identity at either Z pole. A zero billboard camera vector is refused because source normalization is undefined. Inactive particles produce no raster triangles.

Render flags follow [HLSL round](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-round): halfway values round to nearest even. The CPU helper implements this without depending on the host floating-point rounding mode.

The camera expands particle vertices into its existing geometry buffers and preserves floating RGBA, including HDR colour and alpha. The resolved request camera position drives billboarding, so inherited camera settings use the same adapter. Particle capacity joins retained source bytes and flattened geometry remains admitted before allocation. Mirror and scene transform traversal remains shared with ordinary meshes.

`ParticleTransparent` disables depth writes, matching `gpu_set_zwriteenable(!transparent)` in `d3d_object_instancer.gml`. `ParticleBlend` maps Normal, Alpha, Add and Maximum through the pinned `_draw_defines.gml` macros. Normal uses source alpha/inverse source alpha; Alpha uses one/inverse source alpha for colour and one/one for alpha; Add uses source alpha/one; Maximum uses maximum blend equations. These actor settings apply to geometry and colour submissions. Source instancers have an empty `submitShadow`, so particle instances do not cast shadows.

The existing native text value codec does not serialize nonempty `MeshValue3D` payloads. This change preserves particle metadata through owned runtime clones and camera captures, but does not introduce a mesh or scene text serializer. Durable particle simulation records use their replay codec; a retained base-mesh receipt remains subject to the existing mesh persistence limit.
