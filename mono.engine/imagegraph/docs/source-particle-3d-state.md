# Particle 3D state core

`SourceParticle3DState.hpp` is an independent bounded replay stage for pinned `node_3d_particle.gml`. The native `pc.3_d_particle` adapter publishes particle instanced meshes and stores constructor-bound receipts through the existing DataReplay owner. Native camera rendering consumes the separate particle records and floating RGBA. The receipt is owned in-memory replay transport; existing native mesh literal serialization does not support saving its frozen `base_mesh` as an arbitrary authored value. Desktop reference parity remains unverified.

The state retains both source ping-pong buffers. Each slot holds the 64-byte `MeshInstance3D` transform, the separate 64-byte `ParticleRecord3D` and four start-position f32 words. A charge covers both allocated buffers. The default pool is 1024, matching the source Windows instancer; the source other-platform pool is 500. Smaller native capacities may be specified explicitly.

Initialization zeroes all buffers and prepares five curveMap tables with 33 double samples and source tolerance .00001. The source creates these curves initially and does not refresh them each frame. Gradients use exact `eval`, even though the source also builds unused gradient caches. They are not sampled through `evalFast`.

Begin performs loop prerender at frames [TotalFrames-PreRender,TotalFrames), resets only the spawn index, and then steps the requested first frame. PreRender -1 means TotalFrames. Advance accepts the same frame or exactly the next frame; callers must replay intervening frames for a seek. Neither controls nor path pointers survive a call. A path caller supplies a sample-work quote derived from its validated path payload and keeps its admitted `PathRuntime3D` alive through evaluation.

The source operation order is preserved: frame seed and spawn amount; per-newborn seed, velocity, shape-follow amount, spawn position, rotation and lifespan; reseed again for every active slot; acceleration, follow-path ranges, gravity, ground offset, rotation speed, size, scales, random gradient ratio, palette selection and alpha. Equal random_range bounds consume no draws, while irandom_range consumes one and irandom consumes two. Existing `SourceRandom` supplies the documented official HTML5 profile. Desktop RNG parity is unverified.

Movement and colour calculations use double temporaries read from prior f32 buffer words. Every completed slot is stored back as f32. Colour multiplication is `lifetime * (random * palette)` with byte truncation at each multiplication, including alpha; alpha then multiplies the authored amount and curve before its f32 write. Source acceleration is multiplied by lifetime age; movement applies the speed curve again. Ground collision snaps to ground and then still advances by rebound velocity.

Source quirks are explicit. Lifespan death uses `lifeCurrent > lifeMaximum` after increment. Reused slots retain billboard bits and existing direction normals until the source overwrites them. Circle shape-follow direction applies spawn rotation twice. Path/mesh/data spawn ignores Spawn Origin. Highest occupied index is passed as draw count, excluding that final slot. Empty/invalid spawn paths, mesh groups and direct data refuse transactionally instead of reproducing partially updated source buffers. Invalid follow paths disable following, as in the source. Zero/nonrepresentable lifespan, undefined direction normalization and nonfinite/f32 overflow refuse rather than fabricate state.

BBMOD quaternion zero becomes identity; squared length below QuaternionEpsilon is left unnormalized. The native profile uses .00001, matching the untouched HTML5 runner default. [GameMaker documents the current default epsilon](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Reference/Maths_And_Numbers/Number_Functions/math_get_epsilon.htm). No pinned application math_set_epsilon override was found in the archive audit.

Work admission happens before control/state scans, allocation or simulation. Each visited pool slot quotes 512 units plus gradient key work and up to two admitted path samples; validation and initial curve-table generation are included. ProcessorCount shares a 64-million-unit ceiling. Allocation, invalid controls and malformed state leave both previous state and destination unchanged. Focused tests exercise source stepping, reuse, RNG receipts, colour order, alpha, curves, spawn sources, prerender, bounce, gravity, timing, exact ledger refusal and whole-processor refusal. These fixtures passed joined release-tests verification on 2026-10-07.
