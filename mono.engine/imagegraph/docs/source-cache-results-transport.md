# Cache Results freed-slot lifecycle

Cache Results retains source cycle positions after Clear. Native owned images
and the exact private freed-slot record can now coexist in an ordered runtime
array. Homogeneous valid histories use Image Elements; uniformly freed histories
use Struct Elements; mixed histories use the existing Any.Items carrier with
one leaf per source slot. Flat Any Elements remain invalid. None of these records
is a source numeric handle or an invented transparent surface.

The kernel redraws only the current source index. Other freed slots remain
visible as owned metadata, and the successful list update commits to DataReplay.
Sequence copies valid selected pixels; selecting the exact freed slot diagnoses
UnsupportedExecution at surface_in. It protects both direct array selection and
a scalar marker forwarded by Array Get. Unselected markers and ordinary Struct
values keep existing transport behavior. A mixed named list is a value result,
not a drawable image. Image feedback bindings still require a valid selector.

With Amount2, Clear produces [freed, freed], index0. A nonfirst valid draw yields
[image, freed], index0. The next first-frame rotation drops that first image,
shifts the freed position to0 and appends/draws image1. The following first-frame
rotation drops the freed position and yields two images. Nonfirst updates never
advance the index. Amount truncation/growth and first-frame timing remain source
ordered. Missing initial raw pixels and sparse positions keep their diagnostics.

A shared private slot view validates only bounded flat lists of genuine finite
RGBA8 pixels and exact freed records. Nested or unrelated retained records refuse.
Before constructing candidates, the kernel charges candidate Elements, transient
Items, journal copies and output normalization slots, retained leaf buffers and
converted input bytes. Clear charges source/output/replacement overlap before
creating its uniform freed list. Publication or budget failure retains every
preceding journal and output. No generic runtime validator was broadened.

Headless fixtures use compiled graphs for signed fractional direct observations,
valid/invalid Sequence and Array Get selection, exact two-cycle refill order,
Amount shrink/growth, numeric format and dimension conversion, ownership,
malformed shapes, and tight byte caps. Host fixtures cover nonnegative seek and
restart, valid selected images, and refused intermediate invalid selection with
retained last-good output. A native RigidProvider fixture refreshes tick2 at a
positive fractional observation from the pre-frame checkpoint, preserves earlier
rigid journal frames, and keeps unselected freed positions. Direct kernel signed
math is separate from host admission: Cache Results host reconstruction rejects
negative frames; feedback-bound hosts require integer clocks.

The Clear button still performs no graph update. Same-clock dependent previews
wait for a fresh admitted observation. Source scheduler/device numeric handles,
unwritten source pixels, exact desktop drawing/blending and generalized invalid
surface consumers remain reference gates. Joined release66 CPU checks pass eight new core transport cases, the existing
Clear cases and the native rigid checkpoint fixture. Live UI, sanitizers and
source runtime comparison remain open. No timing claim is made.
