# Cooked Composer surface routing

The dedicated pass follows the existing render graph, named texture table and source-image queue. It uses the fixed fullscreen vertex ABI already admitted by `ComposerHlsl`, rather than the scene material vertex ABI. Existing live ShaderScript compilation remains in `ShaderLibrary`. Composer source HLSL is compiled only by an explicit authoring cook.

## Authoring and persistence

The authoring host captures the selected `pc.hlsl` inputs once. `CookNode` compiles the source fragment, validates its paired stage reflection and produces `ShaderData` plus a bounded native document copy. Libraries are caller-supplied source records selected by source library names. No include search path or runtime compiler is introduced.

The Studio action encodes canonical ASH1 bytes and names the immutable artifact `<BLAKE3-of-ASH1>.ashader`. It persists those bytes in the configured local store's `Baked` directory before publishing the document edit. Existing local publication carries those cooked bytes through the ordinary asset delivery manifest. Unreferenced immutable files may remain after a refused authoring edit.

`composer_cooked_shader` is native `Node.SourceProperties` metadata. It is excluded from the source-definition fingerprint. Native format 9 saves retain the selector. It is not an upstream Pixel Composer socket or attribute. Source PXC export retention requires an explicit engine-owned metadata envelope; no source compatibility claim is made for writing an invented attribute.

Installation precedes the undo transaction. A refused new install leaves the authored document unchanged. If undo recording refuses an otherwise admitted edit, Studio removes only that newly installed owner/name/revision. An existing immutable artifact is reused after exact byte/contract comparison. A saved document never depends only on transient renderer cache residency.

`CookerIdentity` records pinned shaderc, glslang and SPIRV-Tools source revisions supplied by the build. This is source provenance, not a claimed compiler release version. Source builds without that provenance require the authoring caller to supply it explicitly. Optional offline MSL requires an explicit translator identity; runtime never translates it. SPIRV is the default Studio cook profile.

## Captured request and lifetime

`BuildSurfaceRequest` reads either an owned `EvaluationSnapshot` or the existing borrowed `HostNodeInvocation` input/image view. The host-provider path does not rerun upstream producers. The shared imagegraph receipt helper admits authored node clones, resolved value payload, string/vector capacities, image hashes and replacement scratch before copying. Core host-recording validation remains authoritative. A retained previous recording is replaced only after the surface and its full receipt succeed. It owns the admitted pair, numeric uniform bytes and source-slot textures before the borrowed capture expires.

Argument kinds follow source order: Float, Int, Vec2, Vec3, Vec4, Mat3, Mat4, Sampler2D, Color. Source vectors and matrices carry exact flat numeric component counts. Matrix components remain in source column order and are packed using reflected strides and major order. Color components use source byte values divided by 255. Missing active sampler images are refused. Optimized inactive declared sampler slots receive an explicit zero image. SPIRV retains source slot numbering; MSL compacts active descriptors with the admitted source-to-backend map.

The library admits at most 64 owners and 4096 programs in total. An owner holds at most 256 cooked programs and 64MiB of logical cooked backing payload. This is not a claim about total allocator or GPU residency. Source requests share the existing four-slot queue, 64MiB captured retained-capacity quota and 128MiB native scratch quota with source camera/SDF work. Captured requests include fixed carrier storage, nested vector and string capacities. Replacement admission also includes the previous output and frozen snapshot. Cook installation separately admits every retained library entry and its vector backing, the caller, candidate and canonical encoding under an operation budget. Entry growth admits old and new backing before any mutation. Immutable-name validation reserves three encoded envelopes because the current codec has a private growing body writer overlapping the exact-reserved final writer; this is a conservative engine carrier allowance, not an allocator peak guarantee. Vendor reflection scratch and allocator bookkeeping are separate from these carrier capacities. Display scratch covers both resident textures, both transfers and CPU staging. Failed edits retain the prior published texture. Admission and recording compare the exact installed pair and revision, and completion rejects obsolete revisions before publication.

## Recovered scheduling

The real graph declares frame-scoped upload, raster and optional display-download jobs. Upload resources are producers of raster inputs. The first completed fence makes raw RGBA8 staging bytes readable. A second graph declares display-upload with those bytes as an external input and the sRGB interpretation texture as its output. Publication follows the second completed fence. SDL requires equal formats for GPU texture copies, so the encoding tag change uses download and upload transfers with identical bytes. `GraphRunner` executes those jobs through the renderer's normal node table.

Composer source jobs record before ordinary view consumers in `FrameBatch`; they use existing tracked transfer, buffer and texture wrappers. Completed textures are adopted through the existing source submission fence ledger, then exposed through ordinary owner-scoped named bindings. A queued image is not advertised as ready. This supports existing named texture consumers without inventing a material map schema or replacing authored materials.

The client reads exact hash-named artifacts from its explicit staged asset root, validates the content address and ASH1 container, and installs them for the real presentation owner. Its content-demand caller reads current ECS bindings through the real world Store and requests cooked names in already parsed documents at the exact same asset-root graph path, even when missing artifacts prevented the first queue admission. A narrow stamp records Store incarnation, observed binding version, live row count, owner, bounded directory and document-cache mutation revision. Unchanged pumps append nothing; edits, removal, directory changes and document reparses invalidate the stamp. Missing or malformed graphs and refused scans never publish a successful stamp. The cache holds at most 64 owner stamps, deduplicates at most 8 cached documents per scan and appends at most 256 program names. A stack-scoped client provider forwards Lua capabilities and captures upstream cooked Composer stages through the same renderer-backed receipt adapter. Source artifact loading does not demand all assets by kind.

The Studio bridge supplies `Universe->NameOf(Active)` from the actual Editor owner context. A stack-scoped provider uses resolved host inputs. Preview uses `CaptureComposerSurfaceAsync` with an explicit caller-scoped capture name. It queues one exact authored/control/image-hash/frame/interpolation recording, returns an explicit pending observation, and retries the completed raw-byte receipt without waiting. A new recording or shader revision supersedes the previous generation. Panel close and owner changes cancel exact names. Studio holds the pending evaluation frame while authoritative playback advances; the completed image retains its actual frame caption. This prevents continuous playback changes from cancelling every capture. Preview cache holds at most 16 captures under 64MiB of reserved receipt/output capacities; it is separate from the source queue and native scratch ledgers. The Editor builds this panel before `PresentWorld`, so manual exports and cook upstream captures use the explicit synchronous method while the renderer batch is idle. Async completion still requires ordinary renderer submissions: a pending capture must wake the relevant viewport presentation while its producer job remains pending. The existing unchanged-scene early return otherwise prevents recording and fence polling. This wakeup is a Studio caller responsibility and does not imply continuous unrelated scene invalidation. Export resource ownership uses the same submission ledger. A failed fence wait leaves resources owned until real completion; it does not release recorded resources prematurely.

## Color and verification profile

Source raster targets use RGBA8 unorm. Captured numeric sampler bytes are uploaded through linear/unorm texture formats, preserving raw source interpretation. Display publication uses two explicitly tracked transfers through bounded raw CPU staging into the display resident format; linear publication retains unorm interpretation. This transfer is an encoding tag change, not a request to apply an sRGB encode during rasterization. R8 follows the existing engine upload profile `(r,r,r,255)` in linear RGBA8; source hardware swizzle parity remains a reference gate. Float and packed input textures use their actual upload layouts; expanded R8/RGBA4 bytes are included in scratch accounting.

CPU contracts cover actual source cooking/reflection, ASH1 encoding and persisted reload, owner/revision rollback, native graph save/reload, argument packing, the borrowed host view and real graph dependency ordering. Standalone runs against moving joined archives are diagnostic, not final acceptance. A fresh joined build must accept all new production and caller fixtures.

GPU checks remain pending user approval: sampler slot holes, source matrix layout/orientation, byte-exact UNORM-to-display copies, generation cancellation, fence adoption, named material/skybox consumers and Studio preview/export. Apple MSL compilation and execution require actual Apple hardware. No physical queue overlap or visual parity is claimed by CPU graph ordering.

Numeric profile: source Int arguments retain raw Generic NodeValue scalars until `buffer_s32` packing. The adapter truncates finite doubles, wraps modulo 2^32 and interprets signed 32-bit. Native int64 values preserve their low 32 bits without a double conversion. Packed numeric Color uses RGBA byte extraction, including the high alpha byte. Source non-surface sampler values skip D3D binding while advancing the source slot; the native profile refuses an active missing sampler rather than depending on unspecified previous device state. Optimized inactive slots receive an explicit zero tile.

Authoring operation ceilings: `CookNode`, `CookArtifact`, paired assembly and compilation accept a caller byte allowance. The caller first deducts its source document, frozen snapshot and owning library buffers; borrowed views do not reveal those capacities. Cooking admits previous outputs and the new captured definition/document, then propagates the remaining allowance into assembled source, owned SPIR-V words, reflected metadata, feature strings and optional translated payload copies. Assembly admits a bounded normalization/declaration scratch allowance and checks string growth before each append. Vendor compiler, reflection and translator internals are separate scratch; their returned executable/text sizes are checked before copying into engine-owned artifacts. These limits are owned carrier capacities, not an allocator or vendor peak-memory guarantee.
