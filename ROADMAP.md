
# ROADMAP

## Editing

Do NOT add new deferred work as a roadmap item. Place it in
`docs/DEFERRED.md`. The existing `Deferred:` blocks below are version history
and pointers to that register. If a TODO item is not FULLY completed, split the
TODO item, keeping the concise short dash point list with block infront and
split it as another item under the same version.

For example, if we complete A and B but not C and D:
```
### v0.5
- [x] do: A1, A3, A5
- [_] do: A, B, C, D
- [x] do: G, H, I
- [x] do: K, K2, K3
```

becomes:
```
### v0.5
- [x] do: A1, A3, A5
- [x] do: A, B
- [x] do: G, H, I
- [x] do: K, K2, K3
- [_] do: C, D
- [_] deferred `D0001` for later.
```

or defer to another version.

## VERSIONS

The milestone headings below are development labels. Not in line with project versioning.

- [x] deferred `D00102`'s decided half — `Engine::bakegraph`, the node vocabulary and the bake document format at `shared` tier, linking `Engine::core` and nothing else. **The point is what it does not link.** `bake` is the only thing in the engine that reads a `.glb`, a `.pmx`, a `.png` or a `.bmp`, and its build file states that nothing a shipped game links may link it — so a save format that named `bake` to parse a *text document* would have put every one of those decoders into `server`, which has no reason to decode a JPEG. The register weighed three ways out and settled on the module split as the honest fix; carrying pipelines as opaque text would have given up the load-time validation the render half has, and putting them on the universe rather than the world trades a dependency question for an ownership question nobody has answered. **It was cheaper than the register assumed**: `GraphDocument` needed only `Graph.hpp` and `core`, `Graph.hpp` needed `assets` — which is what a baked mesh *is* rather than a decoder — and only `Graph.cpp`, the evaluator, reaches an importer at all. `Build` is the one function needing both halves and stayed in `bake`; `IsBareNode` became public because a closed list of parameterless node kinds is precisely the thing that must not be copied. The suites split with the code, so `bakegraph`'s proves the format round-trips with no importer linked. **The `<AssetPipelines>` block was deliberately not written**: `Editor::DrawAssetsPipeline`, `WritePipelines`/`ReadPipelines` and `client::InstallWorldPipelines` are all `TODO(render-pipeline)` markers — the panel this entry described went out with the same revert that took `D00038`'s multi-view seam — and a save-format section with no producer and no consumer is a feature that looks present and is not. The format break is cheap to take later precisely because the module split was the expensive part.

- [x] deferred `D00039` closed — the physics module had a caller for the first time. It was complete, tested, benchmarked and connected to nothing: `RegisterPhysicsSystems` was called from `physics/tests/` and nowhere else, and every world this engine shipped was anchored throughout, so integrate, broad phase, narrow phase and solver had never run against a real scene. **Two things were missing and only one of them was the wiring.** `physics` deliberately has no gravity — its own suites say a top-down game should not have to switch one off, so `RigidBody` carries no gravity scale and the pipeline has no gravity step — which means wiring the pipeline alone integrates every body at zero acceleration for ever. That is not hypothetical: the new case failed exactly that way when it was first written against the pipeline alone, which is how the missing half was found. `scene::Gravity` is the second feature: a resource, so a world under water or on the moon authors its own vector, defaulting to 9.81 m/s² down — Earth's in metres, because this engine measures parts in metres and Roblox's 196.2 is the same acceleration in studs. The editor installs both on every world through one `PrepareWorld`, which also closed a smaller bug on the way: five call sites each wrote the same three lines and the one that wrote two left a world restored by Stop without services. A new **Slide** world is the demonstration — a curved ramp of overlapping boxes, blocks spawning at the top and destroyed ten seconds later — chosen over a stack because a stack tests the solver and nothing else, where a slide asks for all four steps at once and each fails visibly. A block was measured leaving the ramp at x 3.4 after 4.9 s and the earlier ones resting by tick 600. `just determinism` is unaffected: the server was deliberately not wired, because giving it suspension-like behaviour changes a program whose output that recipe compares byte for byte.

- [x] deferred `D00018` closed — what a game replicates is one table instead of three. It was written out in `mono.server`, `mono.unified_server_client` and `mono.studio`, and the entry said all three agreed, "which is the only reason this is an entry and not a bug". **Two of the three still did.** The server and the studio matched row for row; the diagnostic harness was missing `scene.Camera`, `scene.SurfaceCamera` and `ecs.Hierarchy` — a mirror, a lens and a parent link — so the copy whose own comment says it exists to make disagreement observable was the one that disagreed, and nothing observed it. That is the entry's prediction arriving in the least useful place to have it. **The table is `replication`'s now, against the entry's own objection**, and the objection is answered by what actually crosses: this names components the way the wire does, as *strings*, and `Authority::Replicate` already takes a `core::Name` — so the module gains no include of `scene`, no link against it, and no knowledge of what a `Transform` contains. What it is not is the real answer, and that has not changed: a `<Replicated>` section in the game document is a per-game declaration that deletes the table rather than moving it, and is the only version that also lets a game replicate a component `scene` does not own. It is now cheaper, because there is one caller to change instead of three. Four cases pin the pairing, the completeness, the absence of duplicates and the qualification of every name — where before, nothing in the build compared the copies at all.

- [x] deferred `D00021` closed — `AutomaticSize` grows a labelled element to its string, which was the half left open when the container half landed at v0.8. **The blocker turned out to be an argument rather than a dependency.** The entry said the text half needed metrics that are *shared* — a font table below L7 — because `gui` is L7 and `render` is L12, so injected metrics would make a client with an atlas lay a tree out differently from a headless server, a studio and a test. That is true of *replacing* the estimate and irrelevant to *using* it: `Layout.hpp` already states that the backend draws at `Resolved::TextSize` and does not second-guess it, so nothing downstream re-measures and within this engine `AVERAGE_ADVANCE` is not an approximation of the truth — it is the measurement, the one answer the hit test, a headless assertion and the renderer all agree on. A box grown to it therefore fits by the same definition of fitting the module uses everywhere else, and the old refusal's stated reason — "a box the text does not fit" — could not happen. `TextScaled` on a grown axis now returns exactly the size the author typed, by construction rather than by a special case: `FittedTextSize` divides the box by exactly the product the growth multiplies. The other failure the refusal named is still refused and now structurally — a `TextLabel` has no children, and a labelled element is sized from its text rather than from the children path that would have collapsed it to nothing. What remains genuinely open is unchanged and is *not* this entry: the estimate may be wrong about real glyphs, which is the risk `TextScaled` has carried since v0.8, and closing it means metrics shared below L7 rather than a second opinion at the point of use.

- [x] the replicated set is derived rather than listed — everything a world holds that is shared, less a named list of what is local. The allow-list of nine components was the wrong shape for the same reason the three copies were: a component added to `scene` did not cross until somebody remembered, and remembering is what had already failed. **The question a host answers is now which components are *local*, which is a much shorter list and one where every entry has a reason** — `ActiveCamera` and `CameraController` because the client mints its own viewpoint and a replicated one would be a second answer to which eye the world is seen through; `InputState` and `LocalPlayer` because they are the receiving machine's own; `PreviousTransform`, `Rendered` and `QuickHash` because they are rebuilt every frame by whichever machine draws, so sending them is wire spent on a value the far side overwrites; `Transient` because not being kept is its whole point. **`scene.Camera` itself crosses, and that distinction cost a test to find**: it is a *lens* rather than a viewpoint, a `SurfaceCamera` carries one, and excluding it left `AimSurfaceCameras` with nothing to aim — every mirror a flat grey rectangle on every client, caught by `studio.playlink`'s "a mirror arrives on the client whole". A type that is not trivially copyable is skipped too, because everything but the two tick-written components is signature-detected and a signature needs a hash: the three catalogues are resources holding maps, they hang off no entity, and they arrived only by sharing the prefix — declaring them was a warning per host per run. `Authority::Replicate` stays opt-in and unchanged; what moved is where the deciding is written down.

- [x] network ownership — who simulates a body, and who is allowed to say where it is. The question was whether server authority was enforced by anything, and the answer was that it was enforced by there being no other option: the server was the sole authority for everything because nothing else could write, and **the server was not simulating either**. That is the first half — `D00039` gave physics a caller in the studio and deliberately stopped there, so a game hosted headlessly integrated no body and resolved no contact. A part dropped in a hosted world hung in the air and every client watching it agreed, because they were watching an authority that was not simulating. `PrepareSimulation` is the server's half of `Editor::PrepareWorld`, on the two paths that host a real scene and deliberately not on the placeholder, which is a benchmark whose own `Integrate` and `Bounce` are what it exists to measure. Hosting `examples/Slide.luau` headlessly now prints that example's own launch report from a process with no renderer in it. **`scene::NetworkOwner` names a `Player` rather than a `ClientId`** — a client handle is `replication`'s at L11 and this is `scene` at L7, but the deeper reason is that a script is what assigns ownership and a script has a player, not a socket. Absent means the server, so ownership costs an entirely server-owned game one archetype nobody visits. **The wire needed no new message kind**: a delta going up is the same bytes as one coming down, so `Authority::Receive` stopped refusing `MessageKind::Delta` and `Connector::SubmitState` sends one — while a snapshot or a structure message from a client is still refused, because those are a client saying what the world *contains*. **The trust decision is written down as a decision.** Authorisation is ownership, checked per entity per message through a host-supplied predicate; owning an entity does not grant a component, because a client may only write what the server already sends it; and plausibility is deliberately *not* checked in the engine, which does not know whether this game has teleports, launch pads or a grappling hook — a speed limit invented at that layer is one every game works around and none can tune. No predicate means nothing may be written, so the insecure state is not the one you get by forgetting. **The filter runs at the write and that is mechanical rather than stylistic**: a component's values are one packed stream in entity order and only the descriptor knows how long one value is, so stripping entities from a `ComponentDelta` leaves their bytes behind and shifts every later value onto the wrong row — a case that fails with `700.0f == 42.0f`, the unowned client's position landing on the owned part, with every other assertion still passing. **`scene::AddPlayer` had no production caller**, which was the missing link: every world this engine ran had a `Players` service with nobody in it, so `SetNetworkOwner` had no argument obtainable at run time. A connection now becomes a player named for its slot rather than for anything it said, and dropping one destroys it — which is what makes the `scene.ownership` reclaim fire, so a body owned by somebody who left goes back to the server on the next `PreSimulation` instead of being owned for ever by a dead entity. Verified against three real clients over real UDP against a real server process. What did **not** land is `replication::Prediction`'s caller, and the reason is `D00108`: an owned entity is simulated by its owner and never corrected, so ownership describes a third category prediction deliberately does not cover. The larger finding is that nothing has ever called `Connector::Submit` at all — the server's whole rewind-and-hit-test path decodes an input no client has ever sent.
