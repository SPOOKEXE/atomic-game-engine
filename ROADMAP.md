- [x] act on those numbers, first pass — the per-world barrier cost. Three avoidable allocations per world per tick: `Fanout.assign(N, {})` destroyed and rebuilt every world's delivery vector, throwing away the capacity it had just grown; handing an inbox over with `SetResource` **copies**, and a resource column holding a non-trivial type destroys and re-copies on assignment, so every world's delivery buffer was freed and reallocated each barrier; and the per-tick budget reset was a hash lookup and a copy to move eight bytes. Now a resize-and-clear, a vector swap, and an in-place write. **59.9 us to 40.2 us, a third off**, on 50 worlds fanning 2450 deliveries a tick, at +-5-9% — measured against the committed version by reverting to it and back
- [x] act on those numbers, second pass — four wins, each measured against the baseline before and after. **The overlay was clearing its whole buffer every frame**: thirty-three megabytes at 4K to erase two panels covering a fraction of it, which is why it measured fifteen times slower at 4K than at 1080p for four times the pixels. It clears the dirty rectangle instead — an invariant `Resize` and `MarkRegion` already maintained — and went **997 us to 10.2 us, and flat across resolutions**. **`VisitTables` allocated three times per query call** — a vector and a string for the plan key, plus the columns vector — on the hottest non-row path in the engine; a stack buffer and a transparent hash made the hit path allocate nothing, **25% off `CountMatching`**. **`Jobs::For` woke the whole pool for two chunks**: a ten-thousand-row parallel iteration cost 21.7 us against 4.0 serial, so a span must now hold `MINIMUM_GRAINS` of work to be dispatched — **91% off `EachParallel` at 10k**. Resources moved from a hash map to a sorted vector, which is right on its merits but measured inside the noise and is not claimed as a win
- [x] established what `Each` at 500k actually costs, rather than asserting it. The claim that it was at the memory wall was a conclusion with no control behind it, and one figure contradicted it: `EachBatchParallel` gets 2.7x from threads, which a bandwidth-bound loop should not. So the floor was measured — two flat arrays, the same three adds, no query, no table walk, no per-row dispatch. **Raw arrays are 211.7 us at 500k and 39.2 at 100k; `Each` is 203.3 and 40.1.** The ECS costs nothing measurable over hand-written array code, so there is no software overhead here to remove and the serial loop is at the single core's streaming limit. That the pool still buys 2.7x is consistent rather than contradictory: one core cannot saturate memory on its own, several can — which `EachParallel` already does. `benchmarks/Iteration.cpp` keeps the control beside the measurement, because "500k takes 200 microseconds" is unreadable without it: it could be a hardware limit or ten times more overhead than work, and those want opposite responses

- [x] measured what a thousand small worlds actually hold, which is what "chunked column storage" was filed against — and **the measurement moved the item.** A thousand worlds of a hundred entities held **72.7 MB resident against 2.7 MB of live rows**, and the culprit was not the column high-water mark this list blamed: **64 MB of it was entity-directory pages.** `SparseSet` allocates a page whole on a world's first entity, and a page was 4096 slots — of *sixteen* bytes, not the twelve the comment defending the number did its arithmetic with — so every world paid a **64 KB entry fee for existing**, which is invisible with one world and is the whole footprint with a thousand. The first page is now 512 slots and every page after it is still 4096: shrinking them all was tried and rejected, because it gives a large world eight times the allocations, they interleave with the columns and scatter them, and a multi-world tick over 100k entities each came out 8–21% slower across repeated runs. Two sizes cost one branch in the index arithmetic and nothing measurable. **72.7 MB to 16.7 MB, 77% off, with every barrier and iteration benchmark inside its own noise.** Chunked storage itself moves to v0.4 with the number that justifies it and a trigger that is now the right one — see there
- [x] archetype edge cache — the trigger was a measurement, so the measurement came first. `benchmarks/Structure.cpp` is built as a subtraction: overwriting a component already present is the floor, toggling one on and off is the same work plus two transitions, and interning alone is the part a cache could delete. **A transition cost 50.8 ns against 9.2 for an overwrite** — changing an entity's shape was five times writing to it — and **the interning was 28 ns of that**, over half, spent allocating a vector, sorting it, hashing it and taking a process-wide mutex to arrive at the answer it had arrived at the last thousand times. `ArchetypeEdges` caches add-one and remove-one per table as a short scanned list rather than a hash of a composite key, because a lookup that cost what the interning cost would be a cache that bought nothing. **11.99 ms to 6.25 ms on 100k toggles, 48% off, at ±2%**, with the overwrite path unmoved as the control. The one thing that can invalidate an edge is `Observe`, which gives a table a `DirtyBits` column and so changes where a transition lands — every lookup carries a watch epoch and a stale one wipes the cache, because that edge is not a slow answer but a wrong one: the row lands in a table with no bits and the write goes unreported. Proved by reverting the invalidation and watching exactly that test fail. **A removal edge cannot go stale**, for a reason the suite states rather than assumes — the destination is a subset of the source, so anything observed in it is observed in the source too and the source's own table index moves — and the epoch wipes both directions anyway, because a cache that invalidated only the half somebody had the argument for is one refactor from being wrong

### v0.3

Replication. The server has authority and a client simulates its own replica and syncs against it — decided while planning v0.2, which reserves the seam for it (see [v02v03v04.md](docs/retired/v02v03v04.md) §2.12) and builds nothing else. It sits here rather than later so that physics, scripting and rendering are all built against a replicated world instead of being retrofitted into one.

**Where this version actually stands:** the two modules are built, covered and passing — `net` at L11 and `replication` at L12 — and **both programs now link them**: `mono.server --listen PORT` serves its world and `mono.client --connect HOST:PORT` replicates one beside its demo, over a real UDP socket between two real processes.

Worth keeping, because it is the lesson of the version rather than a detail of it: **wiring it up found four bugs that a passing in-process suite could not see.** `EndToEnd.cpp` stands both halves inside one process, where they share a component table, an allocator and a clock — so a snapshot naming a component the other build has not registered, a delta too large for a datagram, a write path that marks nothing dirty, and a client that never speaks first were all invisible. Each is written up in the item below. The remaining open lines are refinements with stated triggers; the mechanism ships.

- [x] `mono.engine/net` at L11 `shared` — the connection lifecycle, framing and channels every one of `upstream/`, `downstream/`, `predict/` and `http/` sits on. `Link` is the state machine: Connecting → Connected → Disconnecting → Disconnected, handshake and idle timeouts, keep-alive, per-tick byte *and* packet budgets with the overflow visible in `ConnectionStats` rather than as a mystery stall. **Time is passed in, never read** — no wall clock in the subsystem whose failures are hardest to reproduce, and a timeout the suite states rather than waits for. `Packet` is the wire format, and it refuses a wrong magic, an unknown version, a channel byte outside the enum, and a length that runs past the buffer; a version mismatch is refused rather than negotiated downward. Sequence comparison is wrap-aware, because a 16-bit counter wraps every eighteen minutes at sixty packets a second and a plain `>` breaks every long match. Unreliable is the default and the stale rule applies to it alone — a late reliable packet is a resend that still has to be delivered
- [x] the transports — `net::Transport` over a loopback hub and an asio UDP socket, both behind one interface a caller cannot tell apart. `Endpoint` is this engine's own value type, so no public header names a socket or an `error_code` and the transport stays swappable. A hub rather than a connected pair, because the two cases only a routed network produces are the two this layer must get right: a datagram from a sender nobody has heard of, and one addressed where nobody listens. UDP is polled from the tick and never calls `run()` — async delivery on somebody else's thread is exactly what a reproducible tick cannot have
- [x] reliability — `ReliableSender`/`ReliableReceiver`: unacknowledged payloads held and resent on their original sequence, `Acknowledge` plus `AcknowledgeBits` retiring up to 33 at a time, and out-of-order arrivals held until the gap ahead of them is filled. Both queues are bounded, because an unbounded one is a memory-exhaustion attack from a peer that simply never acknowledges. Two findings worth keeping: `Link`'s single ack window cannot retire reliable traffic at all — the unreliable counter outruns it within seconds — so the reliable receiver writes its own; and the send window has to bound the *sequence span* rather than the entry count, because payloads retire out of order and one straggler would otherwise become unacknowledgeable forever. The fuzz caught the second
- [x] transport encryption — X25519 agreement into HKDF-SHA256 into ChaCha20-Poly1305, with a `Handshake` state machine that yields two directional keys and a `Sealer`/`Opener` pair that hold no vendor type in a public header. **Nonce uniqueness is structural, not documented**: the counter is private and monotone, a `Sealer` is move-only and a moved-from one is poisoned, and there is no constructor from raw key material at all — the only source is a handshake, which runs once per fresh ephemeral pair. Verified against RFC 7748 §6.1 and RFC 8439 §2.8.2 rather than only against itself, which is how a wrong crypto implementation passes its own tests
- [x] join by full snapshot, then per-tick deltas — `mono.engine/replication` at L12, a new module: `net` carries bytes and must not know what a component is, so the knowledge of entities and tables lives one layer up and the transport stays swappable. `Authority` chunks a snapshot under the datagram limit and spreads it across ticks, then streams deltas; `Replica` reassembles, applies through `Store::Apply` and acknowledges. A client too far behind is re-snapshotted rather than repaired — a repair path is a second way to reach a correct world and only one of the two gets tested
- [x] deltas from `ChangeChannel`'s per-row dirty bits — the third reader of the bits, as planned, with no second record of what changed and no snapshot diffing. `EachChangedBatch` yields *runs* of adjacent changed rows rather than one row at a time, so a delta is a memcpy per run; `EachChangedRuns` is the runtime-keyed form replication needs, because it resolves component names off a wire and cannot name a type at compile time
- [x] client-side prediction of the local player only — `Prediction` keeps the unacknowledged inputs and `Reconcile` retires exactly what the server consumed, leaving precisely what has to be replayed. The buffer is bounded and says when it overflowed: the server may simply stop acknowledging, and the symptom on screen has a dozen other possible causes. The oldest is dropped rather than the newest, because the newest is the input the player just made and can see not happening
- [x] reconciliation — the v0.2 seam used for what it was reserved for. `Store::Apply` merges into a running store, and `Store::CreateAt` is the one primitive a delta needed that a snapshot already had internally: an entity created after the join has to arrive at the sender's exact index *and* generation, or a handle stored inside a component stops meaning the same thing on both machines
- [x] client input submission, and the replica bus refusal — inputs travel on the reliable channel, because a lost input is a jump that never happened and nothing later covers it. Which channel a message takes is decided by its kind inside `Session` and is deliberately not the caller's to choose: that is how somebody eventually makes everything reliable and turns one lost packet into a visible stall. The bus refusal is v0.2's `world::Replica`, and replication routes nothing around it — an operation a client wants performed goes up as an input and comes back as state
- [x] interest management — a predicate per client per entity, with a per-client known set that `Created`, `Destroyed` and `Forget` are all differences against. **Losing sight of an entity is a forget, never a destroy**: a client that conflated the two would delete something still there and then be wrong about it the moment it came back into view. Not deferred

- [x] the joint between the two layers — `replication::Session` binds a `Transport`, a `Link` and the reliable pair, so a message goes out framed by `net::Packet` with a real budget, a real acknowledgement window and a real resend. Proved end to end by six cases running a join and a stream over a loopback transport with real encoding, which is what makes `repo_layout.md` §16.6's claim checkable rather than asserted — there is no configuration in which this path is skipped
- [x] `core::SecureWipe` — one zeroing primitive the optimiser may not delete, at L1. It had grown three private copies: `assets` wiped a signing seed and a grant key, `net` wiped a cipher key and a handshake secret, and each carried its own spelling of the same reasoning. A module may not include another module's private header, so the only place one copy serves all of them is the module every module already links. **Three copies of a security primitive is three chances for one of them to be quietly weakened** — and a key erased with `memset` in a destructor is frequently not erased at all, because the write is dead by every rule the optimiser has. Two overloads, `uint8_t` and `std::byte`, rather than one and a `reinterpret_cast` at every call site: a cast in front of a security primitive is a place for a wrong length to hide

- [x] **`net` and `replication` wired into the two programs** — `mono.server --listen PORT` and `mono.client --connect HOST:PORT`, both link rows added, and one process is now an authority for another over a real UDP socket. `replication::Listener` and `Connector` hold the pump so that the loop is written once rather than once per program; the replicated world is a *second* world in the client's universe marked `world::Replica`, so the demo keeps running beside somebody else's authority and the v0.2 bus refusal is used for what it was reserved for. **Four bugs came out of it, and every one of them was invisible to `EndToEnd.cpp`** — because two halves in one process share a component table, an allocator and a clock. (1) The join snapshot was the *whole* store: every component whether replicated or not, every resource including the bus outbox and the DataStore records, and `DirtyBits` — which a receiving process has never registered, so the join failed outright. It is built from a scratch world holding only the replicated components of the visible entities, which fixes the crash and the contradiction of the opt-in rule in one move. (2) **A delta larger than a datagram was refused by `Link::Reserve` every tick, silently**, because a refusal is ordinary backpressure and a message that can never fit looks exactly like one. Thirty-two entities was already 1365 bytes against a 1200-byte limit: the snapshot had been chunked from the start and the delta never was. A tick's delta now goes out as however many independently applicable messages it takes, all stamped with the same tick — so `Replica` treats an equal tick as another part rather than as stale, which is the second half of the same fix. (3) **A system that writes through `Each`'s mutable reference marks nothing dirty**, so the delta path carried nothing at all: `Set` and `GetMutable` mark, an iteration cannot, and that is the engine's fastest write path. `Store::MarkAllChanged<T>` is the primitive for saying so afterwards — it over-reports by design, because over-reporting costs bandwidth and under-reporting costs correctness. (4) The connector only ever *replied*, and a server on a datagram socket cannot send to an address nobody has written from — so the real client sat silent forever while the suite passed, because the suite's client submitted an input first and the real one does not. Proved by `mono.server/tests/Replication.cpp`, which spawns the actual binary: five cases, including a 2000-entity world whose delta is many datagrams and a case that calls nothing but `Poll`
- [x] the entity-collision hole closed as far as it can be closed without the index range — **`Store::SetAdoptOnly`, set automatically on every store a `replication::Connector` writes into.** A replica now refuses to mint an entity and says so once, while `CreateAt` is untouched, because this refuses *minting* and not receiving. That is the same shape `world::Postbox` uses for a replica's bus writes and it turns the failure from "two different things quietly become one, discovered later and somewhere else" into a refusal at the call. `ecs/tests/Replication.cpp` still reaches the collision by deliberately not setting it, so what it pins is the behaviour of the storage rather than of a replica
- [x] delta compression against an acknowledged baseline — **and this line undersold itself: it read as a bandwidth item and the thing underneath it was a correctness hole.** A delta built from the dirty bits describes exactly one tick, so an entity that moved on a tick whose datagram was lost and then went still was wrong on that client *permanently* — no later delta mentions it, and nothing re-snapshots the client because it is acknowledging happily and is not behind. `Authority` now keeps, per client and per replicated component, the entities whose values have gone out and not been confirmed, and resends them until the client acknowledges a tick at or after the one they left on. The dirty-bit run walk is still the fast path and covers what moved this tick; the carried-over entries are read one at a time, which costs nothing on a link that is not dropping anything. Bounded by the visible world rather than by time — an entry is replaced rather than appended when the same entity moves again, and a re-snapshot drops the lot. Three cases, two of which fail with the resend disabled: one loss of a value that never changes again, a confirmed value falling silent, and ten consecutive lost ticks converging

Deferred:
- D00008 — the single-player `ALLOW_TIER_ESCAPE`, still not declared. The wiring is the reason rather than an excuse: `--connect` talks to a server in another process over a socket, which is exactly the arrangement where the client links no server code, so declaring it now would add an escape with no user. Trigger is a client hosting a server *in its own process*, which wants a game file first
- D00007 — priority under a bandwidth cap, and lag compensation. Both wanted their own plan rather than being squeezed in here, and both now have a written reopen trigger. The first is no longer merely absent: splitting a delta to fit a datagram gave the server a drop policy by accident — whatever is last in the component list — which is worth knowing about before it is mistaken for a broken component. **The bandwidth half was closed at v0.4, and its reopen trigger fired exactly as written — `SendsOverBudget` off zero in a real run. Lag compensation is unchanged. See v0.4**
- D00006 — `replication::Listener` admits a client on its first datagram. `net::Handshake` is built and not wired in; what bounds it meanwhile is a client limit, so the worst case is a full server rather than an exhausted one. **Closed at v0.4: the handshake is wired in behind a stateless challenge, so an unadmitted peer costs nothing. What is left is narrower and is named there — encrypting the stream, and binding the exchange to a server identity**

### v0.4

Planned in [v02v03v04.md](docs/retired/v02v03v04.md) — written when this was v0.3, before replication took that slot.

**Where this version stands:** all eleven items below are resolved. `scene` at L7, `spatial` at L6 and `physics` at L8 are built, covered and passing; `core/types` has its value types; both programs are off their duplicated component definitions and onto `scene`; the entity directory has a reserved range; and the storage layout has been reopened and closed. The layer heights the plan inferred were confirmed rather than assumed — `physics` sharing L8 with `assets` is recorded as a decision in its `AGENTS.md`, with the reason it is safe (the two modules are disjoint, so there is no edge for the layer rule to adjudicate) and the condition that would break it.

**Two of the eleven were closed by a measurement rather than by code, and both measurements contradicted the item that asked for them.** That is the second time this has happened — v0.2's chunked-storage item was moved by the same kind of finding — and it is worth stating as a pattern rather than as two coincidences: an item written from a plausible mechanism, sitting unmeasured for a version, is an item whose premise nobody has checked.

**One thing outside this list is worth more than most of what is in it.** Wiring both programs onto one component set closed v0.3's stated gap: the client now *draws* the world it replicates, rather than replicating it into a shadow component set nothing rendered. `mono.client/include/client/Replicated.hpp` used to be that translation layer and is not any more.

- [x] chunked column storage with a shared span pool — **and the 703 MB figure that justified it finally has a benchmark behind it, because it never did.** Measured on the shape the item names: a thousand worlds that each grew to ten thousand entities and settled back to a hundred held **820.3 MB of accounted storage against 3.8 MB of live rows; they now hold 13.7 MB** (process RSS 620.7 MB to 85.2 MB — the residual is glibc holding freed blocks in its arenas, not the storage, which `malloc_trim` moves by 0.1 MB). A world that was *always* small is unchanged in kind, as expected: that case was v0.2's directory pages and was already fixed. **`Each` at 500k came out 4.6% faster and `EachBatchParallel` 10.2%**, which is not what a layout change was supposed to buy and is the chunks being warm rather than one 6 MB allocation being cold. What it cost is on the record too: structural change is **6-9% slower** — `At` is a directory lookup now, and a removal has to notice an emptied chunk — and one control regressed 13.5% because chunks come back from the pool in release order rather than address order, which is a fixable thing nobody has measured yet
- [x] chunked column storage: **a fixed chunk size was the plan and it is wrong, found by crash rather than by reasoning.** A *resource* is a single-row `Column`, and some are 720 bytes wide, so a fixed 1024-row chunk charges every world **1.4 MB to hold one resource** — a regression bigger than the leak, and one that hits every world rather than only the ones that shrank. Fixed 1024 also cost **8.0% on `Each · 100k`**, which is the `SparseSet` 8-21% scatter precedent repeating exactly as v0.2 warned it would. Shipped instead: **chunk 0 holds 8 rows — the deleted `FIRST_CAPACITY`, so a world that never grows is not one byte worse — and chunk *k* holds `8 << (k-1)`.** Capacity is never more than twice the rows, `ChunkOf` is one `lzcnt` rather than the divide-and-modulo this list predicted, and boundaries are a function of the row index alone so every column in an archetype still divides identically, which is what `EachBatch<A, B>` needs. Cost against the old layout: **+0.4% at 100k**, against +8.0% for the size the plan named
- [x] chunked column storage: **the item's load-bearing claim was false, and no test in the tree could tell.** "Legal against the iteration paths as they stand" is true of `EachBatch`'s *contract* and false of `EachBatchParallel`'s *implementation*: the dispatch decision is made per slice against a 32,768-index floor, so one slice per chunk puts every slice under it and the pool is **never woken** — a 3.5x loss with nothing failing. The chunk split therefore lives inside `VisitBatch` and inside the `Jobs::For` worker body, and `VisitTables` still yields one slice per *table*. Three more sites read a column as one buffer and were not iteration at all — `ClearChanges` and `MarkAllChanged` both `memset` from chunk 0 over the whole row count, which is a heap overrun rather than a compile error. **The clip in `EachChangedRuns` was the one mutation of five that no test caught**: 320 ECS, 69 replication and 27 server tests all passed with runs straddling a chunk boundary, and an unclipped run is a delta that sends one entity's id with another's value — a corruption that shows on a client as objects teleporting. Two cases now cover it
- [x] the entity directory's own leftover, taken in the same pass — and **the plan over-specified it in one direction and under-specified it in the other**. `SparseSet::Free` *does* release pages, contra the fear that it would need an O(FreeList) purge: a page that empties releases every trailing dead page, the high-water mark comes down with it, and a free-list entry naming a released index is discarded once when it surfaces, which is amortised O(1). This was not optional — without it a settled world still held 239 KB, **204 KB of it directory**. What the plan missed is that `Clear` keeps pages *precisely so generations survive*, so releasing one loses the generation and a handle issued at generation 1 comes back **alive**; a retained per-page epoch, kept even when the page's memory is not, makes that impossible by construction rather than by care. Four bytes per page, and it spans both index regions
- [x] the pool, and a trim policy — because **a span pool that never trims relocates the leak and reports success.** Process-wide rather than per-store, since per-store keeps the spares a thousand times over; one mutex, taken about seventeen times per column *lifetime* rather than per row. A hard 8 MiB retention cap, chosen against the item's own measurement — a thousand settled worlds hold 3.8 MB of live rows, so a host at that shape retains less in spares than in data — and pinned by a test rather than described in a comment. Building it surfaced **two pre-existing use-after-frees at exit**, both static-destruction-order: a `Column` destroyed during teardown reaches the chunk pool and the component registry, and both are function-local statics constructed *later* than whatever static owned the store. It showed up as `bench_physics` printing its whole report and then segfaulting, which then made every suite measured after it look slow — so it had been quietly contaminating benchmark runs
- [x] vectorisable component layout — **rejected, and the measurement did not merely fail to support the item, it refuted the reasoning.** The premise was that a compiler cannot vectorise a twelve-byte stride cleanly, so padding to sixteen is the way past the streaming limit. Measured on the standalone control at `-O3`: **twelve bytes is 16.61 us at 100k and 85.63 at 500k; sixteen bytes is 41.93 and 201.54.** The packed layout is **2.4x faster**, and the reason is the exact opposite of the one assumed — a twelve-byte AoS of floats has no gaps at all, so the vectoriser treats the column as one flat float stream and fills every lane, while padding puts a dead lane in every vector. Through the ECS the change was inside run-to-run spread everywhere except `Each over two archetypes · 100k`, which got **14-19% slower**. The acceptance criterion set before the work — *10k and 100k improve by more than 500k regresses* — was not met, because nothing improved. Reverted; `scene`'s components are untouched; the number is written into `ecs/docs/TODO.md` under "Rejected" beside the occupancy flag, so the idea is not re-proposed without new information
- [x] and the finding that came out of rejecting it, which is worth more than the item was: **the same loop is 2.4x faster at `-O3` than at the `-O2` the `bench` and `release` presets actually used.** A compiler flag, not a data-layout rewrite, and invisible for as long as every measurement was taken at the same optimisation level as every other
- [x] **`release` and `bench` now compile first-party code at `-O3`, and the objection was answered rather than waved past.** The fear worth taking seriously here was floating point — this repository diffs two runs byte for byte — so the test was stated before the flag was changed: `just determinism` and `just replay-check` against the `release` preset. **Both byte-identical.** GCC enables neither `-ffast-math` nor `-funsafe-math-optimizations` at any `-O` level, so IEEE semantics never moved. Two places had to change, and the second is the one that would have rotted quietly: first-party targets now *state* `-O3` instead of inheriting `RelWithDebInfo`'s `-O2`, and `mono_add_benchmarks` had pinned `-O2` of its own — the two agreed by coincidence rather than by construction, so the benchmark binaries would have gone on measuring a build nobody ships
- [x] **the suite has now been run at the level that ships, which it never had been.** `release` has `MONO_BUILD_TESTS` off and `bench` inherits that, so *every* test in this repository's history has run at `-O0`. Raising optimisation is precisely what surfaces latent undefined behaviour, so a one-off optimised-with-tests configure was built for the change: **104 suites and 18 `ctest` targets, all pass.** Worth saying plainly because it is a standing gap rather than a fact about this change — nothing in the presets runs a test against optimised code, and nothing noticed
- [x] the measured outcome, on a quiet machine against the accepted `-O2` baseline, **and it is not uniform — which is why it is a table rather than a headline.** Serial row iteration roughly halves: `Each` **-57.1% / -50.7% / -51.4%** at 10k / 100k / 500k, `EachBatch` **-57.8% / -52.4% / -51.0%**, the raw-array control **-59.2% / -52.9%**, and `Tick · 1 world of 100k` **-71.7%**. The solver is **7.6-11.0%** faster and the spatial rebuild **4-9%**. Against that, a handful of paths are genuinely worse at tight spreads: `Each with a narrowing term · 100k` **+11.1%**, the broadphase pair walk **+7.8%**, `intern only · 10k` **+5.3%**, `toggle · add and remove, 10k` **+4.7%**, `CountMatching` **+4.3%**. The pattern is that straight-line work over contiguous rows vectorises and the pointer-chasing around query planning and structural change does not, and slightly resents the inlining. Net 24 faster, 11 slower, and the ones that got faster are the ones the engine spends its time in
- [x] one thing this immediately invalidated, opened as `D00012` and then closed by measuring it: **`Jobs`' dispatch threshold is a ratio between two costs and only one of them just changed.** `DEFAULT_GRAIN` 4096 times `MINIMUM_GRAINS` 8 means nothing below 32,768 rows reaches the pool — a threshold argued from a crossover measured when the serial loop was twice as slow
- [x] and measuring it **disproved the reason it was opened for**, which is the outcome worth recording. `EachParallel · 10k` reading 17.6% slower is not the job system: 10k is *below* the dispatch floor, so that benchmark times the **inline** path and the floor was doing exactly its job. What moved is the optimiser — that body writes one float of a twelve-byte row, and `-O3` turns a stride-12 read-modify-write into shuffles slower than the scalar loop `-O2` emitted. Proved by rebuilding the same translation unit at `-O2` and running both: the parallel row goes 2.12 to 2.44 us and **a new serial control with the same one-field body goes 2.13 to 2.40** — they move together, and neither moves with `Each`'s three-add body, which halves. The two rows were never a fair pair in the first place. A test now requires `Participants == 1` at 10k, twenty-five times running, so nobody re-derives the wrong conclusion
- [x] the crossover itself, re-measured: **~262,144 rows for the cheapest body, not 32,768 and not v0.1's 60-80k** — and the ceiling past it is **1.3x rather than 3.5x**, because at 500k both paths stream twelve megabytes and the limit is bandwidth. The other half of the ratio had never been measured at all and now is: an empty `For` costs **48 ns** to decline, **31 us** dispatched to 23 workers and **2.3 us** dispatched to one. **The handover is linear in the pool, not in the work** — every worker decrements `Batch::Outstanding` under one mutex whether it took a range or not, so a batch waits for 23 threads to queue through it. That serialised join is the thing to attack if the crossover ever has to come down, and it is a rewrite rather than a constant
- [x] **and the decision was to change neither `Jobs` constant, because neither can move.** The two measured crossovers are 262,144 rows and 8,000 rows — 32x apart as rows, and 49 us against 29 us as *serial work*, which is one handover either way. A grain constant is a row count trying to express a duration, so it can only be right for one row cost. `MINIMUM_GRAINS` multiplies every caller's floor including the one that measured; `DEFAULT_GRAIN` would need to be 32,768 to suit the cheap body and would then refuse a handover that pays for `mono.client/src/Replicated.cpp`, which writes a `CFrame`, two vectors and two ids per row. One constant, two jobs, opposite directions — so the values stay and the justification at both is replaced with the numbers, since a stale reason at a constant reads as evidence and is worse than none. That is the *second* stale crossover this version found and nothing in the build notices when such a number goes stale

So the recipe whose entire purpose is "what the pipeline actually enforces" was the one configuration nobody could run. `D00005` says the checks a workflow would run "are written and pass"; that was true of `just check` on the `dev` preset and false of the preset the same file names as the enforcing one
- [x] **a real replication bug that four separate runs had mis-diagnosed as flakiness** — `mono.server`'s cross-process case *"a world too big for one datagram still streams"* failed roughly one run in three under load, and was twice written off as a wall-clock deadline miss. It is not: raising the budget to twenty-four seconds does not help. `Authority::Publish` advanced the snapshot cursor when a chunk was **built**, and `Listener::Publish` discarded `Session::Send`'s return value — so when the reliable send window filled, the refused chunk was never tracked, never resent, and the authority had already moved past those bytes and freed the buffer. 192 chunks, 8 refused, **184 applied** — byte-exact with the reported figure. A permanent hole, a join that never completes, and every later delta refused as stale: **17,865 refusals against 184 applications**. `Authority::Unsent` now takes back what the transport refused and rewinds the cursor and the known-set edits. This is v0.3's delta bug in a path the `EmitDelta` fix did not cover, and the module's own `AGENTS.md` had already written down the shape of it. **40/40 on both presets afterwards, against 9-in-10 failing before**
- [x] two more of the same family, found while fixing it: a `Forget` was never split, so a three-hundred-entity forget is one oversized message the link refuses outright; and `ResnapshotAfterTicks` was measured against the tick number rather than against how far behind the client was, so a client in perfect agreement with a **quiet** world was re-snapshotted every 121 ticks forever
- [x] **`D00007`'s bandwidth half — priority under a cap.** The item's own reopen trigger is `SendsOverBudget` moving off zero in a real run, and the bug above is exactly that: a tick's delta was ~137 messages against a 64-packet budget, so 73 were dropped every tick with the tail chosen by position in a vector. Now a per-client score with a rotation that outranks it, so **nothing starves** — a value that has waited `StarvationTicks` jumps every score, and the bound is `StarvationTicks + ceil(n/k)`, asserted rather than argued. Per client rather than per server, and the header says why: the budget is a link's and there is one link per connection, so a server-wide cap would have to be divided before it could be enforced and that division *is* a per-client cap. Costs nothing when there is no pressure — rows are packed in dirty-bit order first and only re-packed by score if that did not fit. `Statistics::Deferred`/`Stalest` mean "the budget was exceeded" and `ConnectionStats::SendsOverBudget` still means "the link refused", which is the distinction D00007 says people will otherwise get wrong
- [x] **`D00006` — a stranger's first datagram no longer takes a slot.** `net::Handshake` was finished and unused for a version; it is wired in behind a **stateless** challenge, which is the part that matters: the cookie is an HMAC over the peer's address and its key-exchange message, keyed by a rotating secret, so an unanswered challenge costs **zero bytes and stays zero however many are outstanding**. Proved rather than asserted — two hundred distinct endpoints say hello, nothing is allocated, and the *first* of them still answers successfully, which no bounded table would manage. Ephemeral keys come from the OS CSPRNG and **not** from `core::Random`, which is deterministic by design and whose determinism is the whole reason it must never produce a key. Admission is an injectable policy the game supplies, defaulting to one whose behaviour the header states in as many words: it admits anybody who completes the handshake, which proves the peer can receive where it says it can, and nothing about whether it is welcome. `MaximumClients` stays in front of the handshake, because the bound is what makes this a gap rather than a hole. **The stream itself is still in the clear** and both `AGENTS.md` files say so, so that "handshake" is never read as "encrypted"
- [x] the smaller half of `D00006`: an entity with **no** replicated components no longer appears in the join snapshot as a bare row. It leaked a count rather than data, and it contradicted the opt-in rule in the same way v0.3's whole-store snapshot did
- [x] **a registration bug that only one test order in twenty could see.** Reading `PhysicsWorld` off an unprepared store went through `Store::Resource<T>()`, which resolves by `ComponentId` and therefore *mints* one under the compiler's spelling for anything unregistered — so asking a world whether it had a physics resource is what registered it wrongly, and the later explicit `physics.PhysicsWorld` was correctly refused as a second name for one type. The process aborted, in a different case each run, depending on Catch2's shuffle. It is the cross-process hazard the explicit-naming rule exists to prevent, reached from inside a single process: `Components::Find` takes a name and registers nothing, which is what the snapshot loader already uses and what this should have used
- [x] **measured, and it moves a number this file has carried since v0.1**: the serial/parallel crossover for `IntegrateMotion` is **~4096 rows, not the 60-80k** the `EachParallel` default grain was chosen against. The old figure was taken on a three-multiply-add body over twelve-byte structs; a row carrying a `CFrame` and integrating a quaternion is expensive enough to repay the handover an order of magnitude sooner. 20k entities: 80.2 us serial against 28.5 parallel. The grain and the crossover are now deliberately the same number. **Re-measured after the `-O3` change and it moved again — the crossover is ~8000 rows, so a grain of 512 was dispatching a six-thousand-row world into a measured 1.27x loss. `INTEGRATE_GRAIN` is 1024, which is also 9-18% better at every count above the floor because a range costs about 95 ns to hand out whatever is in it.** Recorded because of what it says about the class of number rather than this one: the constant that was *supposed* to be the carefully-measured one went stale within a version, from the same cause as the default it was written to correct

Deferred:
- D00007 — **half closed.** Priority under a bandwidth cap is built, measured and bounded; **lag compensation is not started and is unchanged**, still wanting a server-side history buffer this module deliberately does not keep and a fairness policy that is a game-design decision rather than an engine one. Trigger is still the first hitscan weapon
- D00006 — **the hole is closed and what is left is narrower and now named**: transport encryption of the stream, and binding the exchange to a server identity. The keys are derived and used to confirm the exchange, then destroyed. Until the second one lands the agreement is unauthenticated against a relay, which is why the default policy's honest description is load-bearing
- D00002 — the graph renderer. Untouched; still wants `mono.engine/graph` at L9, which does not exist
- D00004 — Crypto++ in `core` for `core::Random`. Untouched, and its trigger is unchanged: the demo dies at v0.6. Worth noting that `net` now has a *second* reason to link crypto, so the question when the demo dies is narrower than "does anything still need `Random`"
- D00008 — the single-player `ALLOW_TIER_ESCAPE`, still not declared and still with no user. Unchanged: `--connect` talks to another process over a socket, which is exactly the arrangement where the client links no server code

### v0.5

The engine has been full ECS since v0.2 and userland instancing is a façade over it — see [docs/retired/v02v03v04.md](docs/retired/v02v03v04.md) and [v05.md](v05.md). This version makes the façade reachable from script, and **the scene moved a version early**: `Rings.luau` and `Rings.js` build and animate it themselves. What v0.6 keeps is what a scene file cannot yet say — a camera, its own scripts, and the rendering they describe.

- [x] **a property stopped being a component and an offset and became a conversion** — the item below assumed a manifest could be generated from the property lists, and **the property lists were empty and the model could not have described them.** `Classes::Property` was called zero times outside `ecs`'s own suites, and `PropertyDescriptor` was `{component, offset, type, size}`: enough for `Visible`, and incapable of `Size` (a doubled half-extent), `Position` (a sub-range of a `CFrame` whose rotation must survive) or `Anchored` (not stored anywhere — it is whether `RigidBody` and `Motion` exist). Roblox's `Size` is a full extent and `Bounds::HalfExtent` is half of one, so **a member pointer was the wrong primitive**, which is what `scene/AGENTS.md` had been saying under "do not add half of one". A descriptor is now a getter, a setter, the component sets it reads and writes, and a kind — `Field`, `Computed` or `Structural`. One mechanism: a plain field's conversion is generated from a member pointer taken as a *template* argument, which is what makes it captureless
- [x] `PropertyType` gains `Vector3`, `CFrame` and `Color3` — and stays small permanently, because under conversions it describes the **userland value** rather than the storage. `spatial::LayerMask` will never need a case: no property is one, `CollisionGroup` is a `Name`
- [x] `core::CFrame::ToAngles` — the inverse of `CFrame::Angles`, missing since v0.1, and needed the moment a script can read an `Orientation` it will assign back. Intrinsic Y-X-Z, matching `Angles` exactly, because any other Euler order round-trips to a *different rotation*. **The gimbal threshold was wrong first and the reason is worth keeping:** it tested `cos(pitch) < 1e-6`, and at a true pole the quaternion round-trip leaves `sin(pitch)` at 0.99999994, so `cos` reads 3.5e-4 — a thousand times the threshold — while the two matrix elements feeding `atan2` have already lost every significant bit. **A test on the derived angle cannot see that; a test on the operands can.** Now measured from the operands at 1e-3, with a 512-triple sweep and a pole case behind it
- [x] `scene` declares the property surface: `CFrame`, `Position`, `Orientation`, `Size`, `Color`, `Visible`, `Mesh`, `Material`, `CanCollide`, `Anchored`. Roblox's names, for the reason `Part.cpp` already gives about the class tree. Four are plain fields; six are conversions. **`Size` writes two components** — `Bounds::HalfExtent` and `Collider::Extent`, which `MakePart` sets from one number, so a setter moving only the first leaves a part drawn at one size and collided at another with nothing reporting it. **`CanCollide` is the inverse of `Collider::Trigger`, not the layer mask**: clearing a mask to say "no" and restoring `All()` to say "yes" destroys whatever a game configured, and `Trigger` is what Roblox's `CanCollide = false` actually means. Two are named as gaps rather than declared — `Transparency` has no field (it becomes a renderer feature at v0.6) and `CollisionGroup` needs a name-to-layer registry that does not exist
- [x] `Store::GetProperty` / `SetProperty` by name — bytes and a size, size-checked so a `Vector3` handed to a `CFrame` property fails instead of writing twelve bytes into twenty-eight. **The dirty bit came for free and that was a finding rather than a plan:** a conversion reaches its component through `GetMutable`, and `StoreState` already counts handing out a mutable pointer as a write. A replica refuses loudly, because a script author cannot tell "rejected" from "applied and overwritten by the next delta"
- [x] **`mono.engine/script` at L9 — Luau runs.** `Instance.new`, property get and set, `Vector3`/`Color3`/`CFrame`, `print` into the engine log. **The marshalling switches on `PropertyType` and never on a name**, so a property `scene` declares tomorrow is reachable today. Sandboxed as a design rather than a hardening pass: no `os` (wall clock — a script branching on one produces a run that does not replay) and no `debug` (stack frames and upvalues, the library for climbing out of a sandbox), frozen globals, hidden metatables, a memory ceiling through the allocator, and a **step budget counted rather than timed** — a wall-clock deadline would make whether a script finished depend on how busy the machine was. A yield is refused rather than resumed, because v0.6 has to take that decision deliberately and a convenient default here is how it gets taken by accident. The VM is `VENDOR` and no `lua_State` reaches a public header, which is what makes the second VM a source file rather than a second module
- [x] **the test scene is a script, a version early** — `mono.engine/examples/Rings.luau` builds the 512-cube ring scene and `--script` loads it. 1172 frames at 59.9 avg fps, byte-identical determinism and replay still passing. **`DemoPart` is registered by `mono.client`, not by the engine**, which is the part worth keeping: `Instance.new("DemoPart")` goes through exactly the path `Instance.new("Part")` does and neither `ecs` nor `script` knows the class exists. What is scripted is the *scene*; `orbit` and `spin` are still C++ systems over columns, which is the split v0.6 keeps
- [x] **`mono.engine/examples` at L10 — the scene is the engine's, and all three programs load it.** The ring scene lived in `mono.client/src/Demo.cpp`, so only a client could ever build one — and **a scene is not a client-tier idea**: a server authors the same world and replicates it, and the unified harness runs both halves against one. `Orbit`, `Spin`, the `ExamplePart` class and its properties, and the three systems that move it are all here now; `mono.engine/examples/Rings.luau` is staged into the assets tree so any program finds it from any working directory. `--script` on the client, `--game` on the server (a flag that had been accepted and ignored since v0.3), `--scene` on the unified harness. **Proved end to end rather than asserted: the harness reads `512 entities on the server, 512 on the client`, all 512 drawn.** What stays per-program is exactly the part that is: a client adds a camera and a draw list, a server adds neither
- [x] the world extent is measured from what a script built rather than declared by it — **and finding out what "built" means cost a run.** The first version measured `Transform` alone and reported an extent of 1.0 for a scene twelve units across, because *nothing has moved yet*: a script sets `OrbitRadius` and leaves the transform at the origin, and the position only becomes true after the first tick — long after a camera has been framed from the number. Where a thing will be is part of how far a scene reaches

- [x] **the bindings manifest** — `mono.tools/bindings` emits `mono.engine/script/bindings/manifest.json` from the class table: five classes, their trees, their component sets, and every property's type, kind, byte width, writability and the components each side reads and writes. **No offsets anywhere in it**, which is not restraint — a property is a conversion, so there is no byte offset to leak, and rule 4 is satisfied by construction rather than by a disclaimer about which fields survive a recompile. Versioned from the first commit. Component names are sorted rather than left in registration order, because registration order depends on which translation unit ran its static initialiser first and a manifest that changed when a link line moved would fail its own check for a reason nobody could act on
- [x] **`just bindings-check`, inside `just check`** — regenerate, diff, fail on drift, and **proved to fail rather than assumed to**: renaming one property in the checked-in file makes it exit non-zero with the name and the recipe to fix it. Rule 6 is what makes it mandatory, and this repository has twice watched a check rot into a false claim
- [x] **the `.d.ts` and Luau declarations**, generated from the same manifest so the two surfaces cannot drift into two APIs. The TypeScript one is a type root, which is the shape a toolchain consumes in place of `@rbxts/types`; the derived interfaces carry only what each class declares itself, because repeating an inherited property would be a second declaration of one fact that TypeScript would silently accept a narrowing of
- [x] **the concurrency document** — [docs/SCRIPT_CONCURRENCY.md](docs/SCRIPT_CONCURRENCY.md), and it builds nothing: `Universe`, `ExecutionMode`, `Postbox` over four buses, `Ticket` and the barrier all exist. It settles the rule everything follows — **a script may only resume from something the barrier delivers in a deterministic order**, which is narrower than "no yielding" and stricter than "yield freely" — and then what falls out of it: `wait` in ticks with a recommendation to rename rather than redefine, a value-to-bytes codec that must sort keys and produce **identical bytes from both VMs** (one shared test, not two), a cross-world lock that is `MemoryStore::Update`'s versioned compare-and-swap because rule 3 leaves no shared memory to guard, and budgets and replica refusals as part of the contract rather than as implementation detail
- [x] **QuickJS is linked, and JavaScript runs beside Luau.** `Runtime` is an interface; `LuauRuntime` and `JavaScriptRuntime` are two files in one module and adding the second changed no caller — which is what the module's `VENDOR`-not-`VENDOR_PUBLIC` row was for. The extension picks the VM, so `Rings.luau` and `Rings.js` build **the same world** through the same bindings and every program loads either. **Three things the tests caught rather than the design:** `JS_NewContext` adds `Date`, so the context is built from `JS_NewContextRaw` and an explicit intrinsic list; `JS_AddIntrinsicEval` turned out to be required by `JS_Eval` itself, so excluding it produced "eval is not supported" for every script rather than a sandbox, and the global `eval` is deleted afterwards instead; and `JS_AddIntrinsicBigInt` over a raw context leaves an object alive so `JS_FreeRuntime` asserts, reproduced against upstream in isolation. Instances are sealed and scripts run in strict mode, because in sloppy mode assigning to a non-extensible object **silently does nothing** — `part.Transparency = 0.5` would have looked like it worked
- [x] **`Instance.new`, properties and the hierarchy bind to the class table — the same one C++ calls.** A calling convention rather than a second mechanism: `Instance.new` goes through `Store::CreateInstance`, `part.Size = v` through `Store::SetProperty`, and `part.Parent = workspace` through `Store::SetParent`. The marshalling switches on `PropertyType` and **never on a property's name**, so a property `scene` declares tomorrow is reachable from both languages today. **What is not bound yet is named in v0.6 rather than implied**: `.Changed`, `:IsA`, `:Destroy`, `:Clone` and `:GetChildren` all exist in C++ and none of them has a script spelling
- [x] **`--script PATH` stops warning and starts loading**, which closes the oldest bullet in `D00001` — it had been accepted and ignored since v0.1. `--script` on the client, `--game` on the server (ignored since v0.3), `--scene` on the unified harness, and the extension picks the VM
- [x] **the C++ test scene is a script, a version early** — `Rings.luau` and `Rings.js` build the 512-cube ring scene and **animate it themselves** off `RunService.Heartbeat`, composing `CFrame`s the way a Roblox script does. There is no `Orbit` component on that path and no engine system reading one: the engine does not know what an orbit is. `Demo.hpp`/`Demo.cpp` do **not** go away yet, because the C++ path is still what `--entities` builds and is the honest comparison — a scene format and a scripting layer, side by side, with the cost of each on the record
- [x] **`game` is the universe and `workspace` is the world a script runs on**, which is the foundation the rest sits on. `game:GetService` reaches services; `workspace` is the world itself and **not an instance in it**, because a world is what entities live in and making it an entity would put a phantom row in every scene. A script holds one `Store` and no binding hands it another — asserted, not assumed — so **the only way out of a world is a service in the universe**: `MessagingService:PublishAsync` / `SubscribeAsync` over `world::Postbox`, proved across two worlds in one universe. Rule 3 as an API rather than a convention
- [x] the datatypes and globals a scene actually needs: `Instance`, `Vector3`, `CFrame` (with `*` composition and `Angles` in **radians**, matching Roblox, while `Orientation` stays degrees — Roblox's own split, reproduced deliberately), `Color3` with `new` and `fromRGB`, `game`, `workspace`, `RunService.Heartbeat:Connect`, `MessagingService`, `print`, and `nil` as a JavaScript global so one idiom reads in both. The standard libraries a deterministic script may have — `bit32`, `buffer`, `coroutine`, `math`, `string`, `table`, `utf8`, `vector` — and **deliberately not `os` or `debug` in Luau, nor `Date`, `eval` or `Proxy` in JavaScript**, because each is either a wall clock or a way out of the sandbox


### v0.6

Where a world *contains* its scripts rather than being handed one, and where the renderer catches up with what a script can already say. v0.5 made the façade real; what is left is the half a Roblox author reaches for next — signals, the instance methods, the datatype vocabulary — and the rendering those scripts describe.

**The rule everything script-side lands under is already written**: [docs/SCRIPT_CONCURRENCY.md](docs/SCRIPT_CONCURRENCY.md) §1 — a script may only resume from something the barrier delivers in a deterministic order. Every item below that yields answers to it.

**Where this version stands.** The script half is built and measured; the render half is not started. That split is not arbitrary — everything below the line needs `mono.engine/graph/` at L9, and everything above it needed only the class table `scene` already declared. The items are marked individually rather than the version being called done.

- [x] `.Changed` per instance, and the fan-out the projection model creates. `ecs/docs/TODO.md` had the engine half — `OnChanged<T>` is per *type* and Roblox's is per instance, so filtering a whole-world signal per script would walk every change for every connection. The half nothing had written down: **one component write maps to N property names**, so writing `Transform` fires `CFrame`, `Position` *and* `Orientation`. `PropertyDescriptor::Reads` is exactly the map that needs, which is why it was declared rather than left to a conversion to know privately. `script/src/Changes.cpp` is the fan-out; it subscribes **once per component for the whole world** and filters to watched instances with a hash lookup, so the cost scales with what somebody watched and not with what moved — `benchmarks/Surface.cpp` measures 97 ns per watched instance and 1.9 us for a quiet tick. Fires at the **next** beat rather than at the write: `FlushSignals` queues, `Heartbeat` drains, and firing at the barrier instead would put a handler's own writes on the far side of the next `ClearChanges`
- [x] `RBXScriptSignal` and `RBXScriptConnection` as real types — `:Connect` returns a connection with `:Disconnect` and `.Connected`, and `:Once` besides. `script/src/Signals.cpp` holds the ordering rules **shared by both VMs**, because ordering is what a recording depends on: insertion order, a connection made during a fire does not fire in that pass, a disconnection during one takes effect immediately, and a handle is never reused so a double-disconnect kills nothing. No `:Wait()`, and that is the design — a signal fires from inside a handler pump, which is not a barrier
- [x] the instance methods that existed in C++ and had no script spelling: `:IsA`, `:Destroy`, `:Clone`, `:GetChildren`, `:GetDescendants`, `:FindFirstChild`, `:IsDescendantOf`, `:ClearAllChildren`, `:GetPropertyChangedSignal`, and `Instance.new(class, parent)`'s second argument. `workspace` answers `GetChildren` and `FindFirstChild` too, which needed `Store::EachRoot` — the world heads no sibling list, so `EachChild(NULL_ENTITY)` could never have answered it
- [x] **`task`, and the yield rule made real** — `task.wait`, `task.spawn`, `task.defer`, `task.delay`, `task.cancel`. §2 settled the unit and the spelling: seconds in, **ticks underneath**, rounded up so a wait is never shorter than asked; and `wait`, `spawn` and `delay` are refusals that name their replacements rather than absences. A yield is legal now **only when something is scheduled to resume it**, which is a lookup rather than a judgement — v0.5 refused every yield because nothing could
- [x] **the value ↔ bytes codec**. `script/src/Codec.cpp`, and every one of §3's three requirements is a property of the *format* rather than of either binding: keys sorted **by bytes** (not by either language's collation — `strcoll` and UTF-16 code units answer differently and neither may reach the wire), a number always eight bytes so the encoding cannot depend on the value's history, and depth, size and cycles refused rather than truncated. `MessagingService` takes a table now
- [x] `RunService:IsServer()` / `IsClient()` / `IsStudio()` (studio defaults to false), plus **`IsReplica()`, which is not Roblox's and is the more precise question** — `IsServer()` is about the host and a single-player process is a server whose client-side world is still a replica. `Store::SetProperty`'s refusal now names the replica case so a script that did not ask first is told why
- [x] **`Enum` as a property type.** `ecs::EnumTable` holds the named sets, `PropertyType::Enum` and `PropertyDescriptor::EnumName` carry which, and `Store::SetProperty` checks membership — so `part.Material = "Plsatic"` is refused where it was written rather than landing in a component. `Material` is the first, with Roblox's set. The manifest lists the enums and both declaration files emit **branded** aliases, so `Enum.EasingStyle.Linear` does not type-check against a `Material`
- [x] the datatypes a game reaches for once it is past a scene: `Vector2`, `UDim`, `UDim2`, `Rect`, `NumberRange`, `NumberSequence`, `ColorSequence`, `TweenInfo`, and `Random` over `core::Random` — **which is what closes `D00004`**, because a script with a seeded generator is the consumer that item was waiting for. `Region3` and `Ray` are shims over `core::AABB` and `core::Ray`, which the engine already had; adding a second spelling of either would have been the duplicate `AGENTS.md` calls the most expensive kind of debt. `RaycastParams`/`RaycastResult` are **not** done — they want `spatial`'s queries bound, which is a script-to-physics edge this version did not open
- [x] `DateTime` and `tick`/`time`/`elapsedTime`, all over `store.Time()`. **`tick()` returns the tick count and not a Unix timestamp**, which is a deliberate break from Roblox: the name is right for what this engine counts, and a `tick()` that returned real seconds is the single most effective way to make a recording stop replaying. `DateTime.now()` refuses and names `fromSimulated()` and `fromUnixTimestamp(n)`
- [x] `typeof`, `warn`, and the base-library gaps. `typeof` is **not** a bound global — Luau's is a fastcall builtin the VM reaches directly, so the mechanism is the `__type` metafield, which every value metatable now sets. `loadstring`, `getfenv`/`setfenv` and `require` are refusals that say why rather than absences
- [x] **`CollisionGroup`**, and the name-to-layer registry it needed. `spatial::CollisionGroups` — beside `LayerMask`, because that module owns the bits and `scene` deciding a naming scheme would be a component module choosing a physics policy. A **name** crosses and never the index; the setter writes the layer *and* the mask from the matrix, and a group nobody registered is refused rather than silently defaulted
- [x] **`Transparency`'s component half** — a float on `scene::Visual`, bound as a property, distinct from `Visible`. The struct grew by four rather than absorbing `Reserved[3]`, and `scene/tests/Components.cpp` caught that the moment it happened. **The sorted pass is not done** — see below
- [x] **camera from script.** `scene::Camera` is a class now, deriving from `PVInstance`, with `FieldOfView` in degrees over the stored radians. `workspace.CurrentCamera` reads and writes `ActiveCamera`, refuses an instance carrying no `Camera`, and keeps the consumer's aspect ratio across a change
- [x] **`MemoryStoreService` and `DataStoreService`.** A `Ticket` suspends the caller and the barrier's reply resumes it, which is §1's *first* legal source — a coroutine in Luau and a promise in JavaScript, both resolved by the host. Tested against a **real `Universe`** rather than a bare `Store`, because asserting on the script alone would have proved a promise was made and nothing about whether the barrier kept it. That test found two bugs a bare store could not have: `lua_resume` returning `LUA_YIELD` was being read as failure when a resumed script called a second store method, and `emplace` was silently keeping the *stale* thread reference. §5's refusals are values a script can test — `Ok`, `NotFound`, `Conflict`, `OverBudget` — and a replica's write is refused against **both** the bus's `Replica` resource and the store's adopt-only flag, because those are one fact recorded in two places
- [x] **the second consumer for every binding, which is the point of having two VMs**: every item above lands in Luau *and* JavaScript. `JsSurface.cpp` and `JsDatatypes.cpp` are the second half, and **everything about ordering is shared rather than reimplemented** — one `SignalTable`, one `ChangeQueue`, one `TaskQueue`, one codec, so which handler fires first and which tick a wait returns on are answered once for both languages. What differs is what the languages differ about: `a.mul(b)` and `a.Equals(b)` because JavaScript has no operator overloading, `typeOf(v)` because `typeof` is a keyword it cannot rebind, and a **`Promise` rather than a coroutine** — resolved by the host at a barrier, which is the same contract and legal for the same reason. `Random` is asserted to produce the *same sequence* from one seed in both, which is the strongest form the shared-machinery claim takes
- [x] **scripts are instances in a world, loaded from it rather than from a flag.** `Script`, `LocalScript` and `LuaSourceContainer` are classes; `Source` names the file and `Disabled` is a tag, so a disabled script is in another archetype and the run loop never visits one. `Runtime::RunWorldScripts` runs them in **creation order** — one script may build what another expects to find — filtered by the host's role, which is Roblox's own `Script`/`LocalScript` split. Each chunk gets a `script` global naming itself, set on the *thread* rather than the state because `luaL_sandboxthread` gives each chunk its own globals. **The source is a path and not the text**, which is the v0.6 shape: an unbounded string is not trivially copyable, so it could not be a column or cross a bus, and `Visual::Mesh` is a `core::Name` for the same reason. The example scene now creates its own `Script` instance, so the world contains what animates it
- [x] transparency's **sorted pass**. `scene::OrderForDrawing` partitions a draw list into an opaque head and a transparent tail sorted back-to-front from the eye, and the renderer draws the two as two ranges of one buffer through `first_instance` — a second pipeline with blending on and **depth writes off but the depth test on**, so a pane is hidden by a wall in front of it and does not erase the pane behind it. - [x] **`mono.engine/graph` at L9, and the pipeline it describes.** The module is `shared`, which is load-bearing: a headless host publishing a view culls it with the same arithmetic. **The split is what makes any of it testable** — a frustum test is six dot products and can be asserted against, a draw call needs a GPU and can only be looked at. `Frustum` extracts six planes from the view-projection matrix rather than from a camera's fields, so it cannot disagree with what was actually projected; `Cull` produces an index list that composes with the ordering; `FitDirectionalLight` frames the shadow map, fitted to the scene's bounding **sphere** so the map does not resize as the sun turns and make its own edges crawl; `Pipeline` is the stage list with the one check that matters at five passes — a stage reading a target nothing earlier wrote, which on a GPU is a frame lit by whatever was in that memory rather than a crash. `RENDER_PIPELINE.md` is not in this repository — see the note at the top of this file — so "stages 1 to 7" could not be followed by number and the line's own text was built to instead

Front faces are culled into the map so self-shadowing acne lands behind the surface that would show it, and the fragment bias is **slope-scaled**: a constant one large enough to stop an edge-on surface shadowing itself is large enough to detach every shadow from its caster. Four taps in a rotated square, which is a soft edge rather than a filter — the difference between four and one is most of what a viewer notices and the difference between four and sixteen is not. - [x] **surface camera.** `scene::SurfaceCamera` on a camera entity makes it render into a texture instead of onto the screen; `Visual::Surface` on a part names which one it shows. **`world::ViewChannel`'s shape with a texture on the far end.** The surface pass runs before the screen pass, so what a mirror shows is *this* frame. **The two ping-ponged textures buy legality and not recursion, and this line claimed both until the claim produced a visible bug**: binding a render target as its own sampler is undefined behaviour, and writing one while binding the other fixes that — but a mirror inside a mirror never happened, because surface instances are partitioned out of the surface pass and so no mirror is ever drawn into a mirror's texture. ### v0.7

**Where this version stands.** The editor is built, drives all three programs off one game file, and has had several rounds of work since the items below were first written — a render gate, a keybind table, a world lifecycle, the shadow half of the draw list and the recording contract, all recorded here rather than left in the commits. **Three items are open and none of them is the editor being unfinished**: porting Roblox places waits on a class tree that does not exist yet and is a trigger rather than a task; a frame of input latency is an ordering problem inside `Renderer::Render`; and the server-view/client-view split needs a host driving two views. Each is stated below where it was found.

- [x] **`mono.studio`, and `RunService:IsStudio()` is true in it and in nothing else.** `script/Runtime.hpp` has carried that sentence since v0.6 with the default set to `false`, on the grounds that editor-only behaviour must never appear in a shipped game because a default was optimistic. `Editor::BeginRun` is the one place in the repository that sets it, and the three programs disagree the way they should: the studio reports `studio = true, server = true`, `server --game` reports `studio = false`, and `client --game` reports `studio = false` while being both halves. The `game -> universe, workspace -> the world this script runs on` mapping needed no new code at all — `Services.cpp` established it at v0.6 and the explorer draws exactly that tree, so what an author clicks and what a script reaches through `game` are one object rather than two models kept in step
- [x] **the game file, and it is a different format from a snapshot on purpose.** `mono.engine/game` at L10 `shared`: a `<Game>` holds a `<Universe>` and one `<World>` per subworld, each with its instance tree and its script text. `world::Universe::Save` already writes a binary snapshot and keeps working — that is a *running* universe frozen mid-tick, same-build only, and restoring one into another build was never promised. A game file is authored content: it has to survive an engine version, read in a diff, merge between two people and be repairable by hand. **Nothing in it writes an entity id**; an instance carries a document-local `id` used only to resolve references inside the same file, which is rule 4 arriving at a save format. **Properties equal to their class default are not written**, so a scene of a thousand parts is a file somebody can read the diff of — and the consequence is stated rather than hidden: a file loaded by a later build picks up that build's defaults for anything it did not name, which is the behaviour you want and the choice Roblox made

- [x] **safe XML, and the subset is the feature.** No DTD, so no billion laughs and no quadratic blowup; no external entities, so no XXE; no processing instructions, no namespaces, no schema. - [x] **`Visual::CastShadow`, and the draw-list arithmetic moved to where a test can reach it.** A part can be excluded from the shadow pass without being excluded from the frame — the property is bound in both languages, in the manifest and both declaration files, and it crosses a save. The interesting half is `scene::ScenePlan` and `OrderScene`: the renderer used to compute its own mirror partition and caster partition inline, and **those counts are `first_instance` and a draw count — the part of a pass easiest to get wrong by one and impossible to see in a screenshot.** A shadow range short by one loses a caster somewhere off screen and the frame looks fine. It is arithmetic over a `shared` type, so it belongs beside `OrderForDrawing` where a headless suite can assert on it, and the renderer is left with the part that genuinely needs a GPU. **The shadow pass draws two ranges rather than one, and that is forced rather than chosen**: the surface pass needs the non-mirrors contiguous from zero and the shadow pass needs the casters contiguous, one partition cannot give both, so the casters are partitioned *within* each run — the mirror half being zero in every scene with no mirror in it. Every partition is stable, for this file's standing reason: an opaque scene must come out exactly as it went in or a recording stops replaying
- [x] **two viewports were thrashing the driver's allocator, and it did not stay inside this process.** One shared depth texture is correct for one viewport and catastrophic for two: the panels are different sizes, so each `Render` found the other's dimensions and reallocated — a colour-sized D32 texture destroyed and created **twice per frame, every frame**. That is what "resizing makes my whole desktop lag" was, and it is not a frame-rate symptom, which is why nothing in `--profile-snapshot` had shown it. Each scene slot owns its depth buffer now, sized to the block-rounded allocation rather than the drawn rectangle because SDL requires colour and depth dimensions to match, and released outright rather than retired — nothing samples a depth buffer, so no recorded interface bind can be pointing at it and the grace period the colour target needs does not apply. **The depth format is chosen at start-up instead of hard-coded**, which was the second bug in the same file: `SDL_gpu.h` says outright that only D16_UNORM is guaranteed and to check which of D24/D32 exists, and D32_FLOAT was written in four places. On the first GPU without it the texture creation fails, the frame is dropped and nothing says why — a black window. Asked once, for both usages at once, because the shadow map is sampled as well as targeted and a second format would be a second thing to keep in step with a pipeline
- [x] **one table naming every key in the editor, and rebinding is why it exists rather than a `switch`.** `input::Actions` opens with "the one table in the engine that names a key; everything else asks for an action" and the editor had drifted from it — F5 was spelled out in `DrawShortcuts`, again in the Run menu's label and a third time in a comment. The editor cannot use that table: it is SDL keycodes through a polled `ActionState`, and the editor's keys are read through imgui, which owns the keyboard while a text field has focus and must go on owning it. So it is the same idea over `ImGuiKey`, deliberately a second table, with a Keybinds page that searches, rebinds, reports the conflict it is about to take and resets. **The part that could not have been left out is `Scope`** — Global, Viewport, Tree, Script — because without it the only available guard is `io.WantCaptureKeyboard`, which answers "is a text field focused" and not "does this key mean anything here": Delete belongs to the tree and the viewport and is a character in the script editor, so a binding on a plain letter could never have been added safely at all. `ShowStatistics` and `ShowFrameGraph` ship **unbound** rather than moved to a different pair of function keys, because F5 is Play in an editor and always will be, and inventing a second set is a decision for whoever wants them — which is what the page is for
- [x] **and now it is enforced rather than recorded.** The decision above was a paragraph in this file and nothing else: a second viewport recording from a worker would have produced a driver validation error or a frame of somebody else's geometry, neither of which points back at the thread that caused it. `Renderer::Render` and `Shutdown` abort unless they are on the thread that called `Initialise`, which is `ecs::Store::RequireOwningThread`'s shape and its argument — by the time a second thread is inside, it has already recorded into a buffer another thread is filling, so there is nothing left to decline and the stack at the violation is the whole value. **The owner is claimed by the constructor and re-claimed by `Initialise`, and that is what makes it testable**: `engine.render.passes` exercises the contract with no GPU, on a build machine that has none. Deliberately **no `BindToCallingThread`** beside the store's — a store is picked up by a different worker every tick and a device is not, so a public rebind would be a seam for exactly what this forbids. `render/AGENTS.md` says it too now, and says it as a contract rather than as a note
- [x] **the sixth pass had a half-updated check behind it, found while writing the one above.** `tests/Passes.cpp` compares `render::PassOrder` against `graph::StandardPipeline` by count and by order, and that comparison did hold when `interface` arrived — it is generic. The *names* test beside it is not: it spells out five passes by hand and `interface` was never added, so it was the one pass whose name nothing checked. The file's own header had gone stale the same way, still describing "five passes". Both fixed, and the count is now deliberately not written down in that file — it said "five" until v0.7 made it false, which is the failure the file exists to prevent happening one level up inside it

Found while building this, and fixed here rather than filed:

- **`scene::Visual` had a hand-written serialiser that two later fields never reached.** `Transparency` and `Surface` were added after `WriteVisuals` was written and neither crossed a snapshot, so a glass pane turned solid the first time a world was saved and reopened. Invisible for an opaque part, which is why it survived three versions. A field added to a type with a *generated* serialiser crosses for free; one added to a hand-written pair crosses only if somebody remembers, and nothing in the build checks — `mono.client/tests/Presentation.cpp` is the cheapest test for that whole class of bug and now covers it
- **The replica's draw path dropped the tail of `Visual` — the same silent loss as the serialiser above, arriving through a different door.** `CollectReplicated` copied the first few fields and left `Transparency`, `Surface` and `CastShadow` at their defaults, so a glass pane replicated as solid and a mirror replicated as a plain part. Two hand-written copies of one struct's fields is two places to forget, and neither forgetting is visible on an opaque part — which is why the pair of them survived together
- **`client::DrawList` was unregisterable, and the abort landed in a world that had never heard of it.** `ecs::Components::Of<T>` caches its answer per type per process, so **the first mention of a type anywhere decides its name** — and in the replicated world that first mention was a `SetResource` rather than `RegisterClientComponents`. The world built next then tried to register `client.DrawList` properly and aborted, naming a type its own function never mentions. Rule 4's failure mode exactly: the compiler's spelling wins by arriving first, and the diagnosis surfaces one caller away from the cause. `BuildScriptedWorld` and `InstallPresentation` had both opened with the registration call for this reason; this path was the gap
- **`game:GetService("Workspace")` found nothing, and an orphan claimed to be in the world.** The global is spelled `workspace` and the service lookup went through `lua_getglobal`, so asking for the service by its class name — which is what a Roblox script does — was refused for an object the engine plainly provides. It resolves from the registry now, so the global, `game.Workspace` and `GetService` are **one instance rather than three handles that compare equal**. Separately, a null `Parent` used to hand back `workspace`, which made every orphan look like it was in the scene — the answer is `nil`, and that is where "an orphan is not in the world" starts being true
- **`scene::CapturePreviousTransforms` moved into `scene`.** It was five lines inside `examples::LoadScene` and the studio needed the same five. Two copies of a *system* is worse than two copies of a helper: both can be installed into one world and the second wins silently every tick

Deferred, and named rather than discovered:

- **One VM per world, and it is Luau.** A world whose scripts are JavaScript runs nothing in the studio, the server's game-file path or single-player. `script::LanguageOf` picks per file and the runtime is per world; reconciling those is a design decision rather than an oversight
- **No undo.** Every editor action is applied straight to the store. Undo needs a command log, and a half-undo covering property edits but not deletions would be worse than none
- **No viewport picking, no gizmos, no reference picker.** Selection is the explorer's; a click in the world does nothing, and a `PropertyType::Reference` shows its target's name and cannot be changed
- **Headless runs no interface backends.** The imgui context starts and its platform and renderer backends do not, so panel *drawing* is skipped — a headless run exercises the universe, the scripts, the presentation phase and the render. Driving the panels themselves without a window needs the backends replaced rather than skipped, which is the shape a scripted or agent-driven editor will take
- **A capture is the world and not the editor.** The chrome is drawn onto the swapchain and SDL does not promise that is readable. Capturing the whole window means rendering the frame into an offscreen target and blitting it, which is a change to every program's frame for a benefit only the editor has
- **Replication is still one world per connection.** A game of several scenes simulates all of them and streams the first, which the server says in its log rather than leaving a player to wonder which world they joined
- **`scene::SurfaceTable` is not written to a game file.** Materials are registered by scripts, so a loaded world rebuilds its table when its scripts run. The moment the studio lets somebody edit a material by hand that stops being true, and `game` gains a `<Surfaces>` section

### v0.8

**The scripted interface**, which is v0.7's last question answered rather than
deferred. The ask was: should the studio's own UI be authored in TypeScript,
with the Roblox `GuiObject` tree as the widget set and React as an option? The
answer is yes, and **not by writing fifty class registrations first**.

Those classes are shims until three things exist underneath them, and a shim
that nothing draws is an API with no caller — which is the thing this repository
refuses everywhere else. In order:

- [_] **`core` gains the value types the tree is made of.** `UDim`, `UDim2`,
  `Vector2` and `Rect` are already in `core/types` and **none of them is a
  `PropertyType`** — so a component holding a `UDim2` cannot be a property, cannot
  be saved, cannot appear in the properties panel and cannot be set from a
  script. `ecs::PropertyType` is a closed list that grows when userland gains a
  value, and this is that. Four cases in `game::Values`, four widgets in the
  properties panel, four in each binding. Small, and everything below needs it
- [_] **`mono.engine/gui` at L7 `shared` — what a 2D thing *is*.** The class tree
  as `ecs::Classes` registrations over real components, exactly as `scene` does
  for `Part`: `GuiBase` → `GuiBase2d` → `GuiObject` → `Frame`, `CanvasGroup`,
  `GuiButton`(`TextButton`, `ImageButton`), `GuiLabel`(`TextLabel`,
  `ImageLabel`), `ScrollingFrame`, `TextBox`, `ViewportFrame`, `VideoFrame`;
  `LayerCollector` → `ScreenGui`, `BillboardGui`, `SurfaceGui`, `PluginGui` →
  `DockWidgetPluginGui`. **`shared`, not `client`** — a server authors a
  `ScreenGui` and replicates it, so a type only a client could name would be a
  type only a client could build one out of. That is `scene`'s argument and it
  is the same one
- [_] **Layout, which is arithmetic and belongs beside the tree.** `UDim2`
  against a parent's absolute rect, `AnchorPoint`, `SizeConstraint`, and the
  `UIListLayout`/`UIGridLayout`/`UIPadding`/`UIAspectRatioConstraint` modifiers.
  One pass, parent before child, producing an `AbsolutePosition` and an
  `AbsoluteSize` per node — which is a component, so the renderer reads it with
  a query and nothing walks the tree twice
- [_] **`gui` rendering at L12, as a render pass.** Rectangles, nine-slice,
  text and clipping — which is a batched quad pipeline plus a glyph atlas. The
  atlas is the part with a decision in it: `ui` already owns four faces for Dear
  ImGui, and a second rasteriser for the same four files would be two answers to
  "what does this glyph look like". `Pass::Interface` is the seam it attaches to
- [_] **Input routing.** Hit testing back to front, `ZIndex`, `Active`,
  `Selectable`, and the `InputBegan`/`InputEnded`/`Activated` signals — which is
  `script::Signals`' shape applied to a tree rather than a new mechanism
- [_] **`GuiBase3d` and the adornments** — `SelectionBox`, `Handles`,
  `ArcHandles`, `BoxHandleAdornment` and the rest. **This is what gives the
  editor gizmos and viewport selection**, which v0.7 deferred, and it is worth
  doing after the 2D branch rather than before: an adornment is a 3D thing drawn
  with the 2D tree's input model
- [_] **`GuiService`, `Path2D`, `GuidRegistryService`** — the services around
  the tree, once there is a tree for them to be around
- [_] **The studio's own panels, authored in TypeScript.** This is the point of
  all of it and it is the *last* step, not the first. `mono.studio` keeps Dear
  ImGui until the engine's own UI can draw a property grid — because an editor
  half on each is two widget sets, and the rule against two ways to do one job
  applies hardest to the thing you look at all day. React is a reconciler over
  the tree once the tree exists; `react-lua` or a hand-written reconciler are
  both reasonable and neither is a decision that has to be made yet

**Why not do the shims now, stated so nobody re-asks.** Fifty registered classes
with no layout, no rendering and no input would put `TextLabel` in the insert
palette, let somebody parent one under a `Part`, save it into a game file — and
then draw nothing, forever, with no error. That is worse than not having it: it
is a feature that looks present and is not. The order above is the order in
which each step has a caller.

The rendering and camera work this version already carried, unchanged:

- [_] `mono.engine/examples/Mirrors-4-worlds.luau` and `.ts` — split-screen across worlds running in parallel via multi-process. Four `ViewChannel` producers and one compositor, which v0.2 already built and `--worlds N` already drives with a synthetic scene. This demo is what proves the cross-process view path end to end. Both files exist and are empty, same as the v0.6 pair. **Four rather than the two this line used to say**, because the names in the tree are the ones the ports will take and two of anything is the count at which a bug in the placement loop still looks like correct behaviour

### v0.9

- [x] local filesystem content delivery network (cdn) — `mono.cdn` and `cdn::ContentRoot` landed early, at v0.2
- [x] cdn content addressing — `Engine::assets` at L8 `shared`: `ContentHash` (BLAKE3-256, checked against the published vectors rather than against itself), `Chunker` (gear rolling hash, FastCDC normalised two-mask cut, table generated from a stated seed so 256 frozen constants are reviewable as an algorithm), `HashTree` (Merkle with a tagged interior and the leaf count sealed into the root, so neither a subtree nor a duplicated node can pass as a whole tree), `Signature` (Ed25519 over a domain-separated message, one signature at the root and none below it) and `Manifest` (the four-level tree, canonical order, byte-stable output, and a reader that recomputes every root rather than believing it). BLAKE3 vendored. `CDN.md` §2
- [x] cdn grants — `assets::Grant`: an HMAC-SHA256 token naming bundle roots, a session, an absolute expiry and a byte budget, plus `cdn::Gate` as the origin's whole authorisation surface. The MAC is checked before any field is acted on and compared in constant time; forged, expired and out-of-scope are counted apart so an alarm is not buried in ordinary events; a grant names content hashes and has no field a path could occupy; `nowSeconds` is passed in so neither end holds a clock of its own to drift. `CDN.md` §4
- [x] cdn group assembly — `cdn::Grouper`: self-sufficiency first (an affinity is never split, even past the ceiling, because half a scene makes nothing appear — and the oversized group is counted rather than hidden), then a size mix that falls out of largest-first packing rather than needing a rule of its own, then priority. Deterministic, because two origins that group the same content differently cache different bundles and nothing reports that they stopped sharing. `CDN.md` §5
- [x] cdn group compression — `cdn::GroupCodec` and `cdn::Dictionary` over vendored Zstd: per group and never per file or per manifest, chunks left uncompressed at rest so dedup works on them, dictionaries trained per build and content-addressed so they version like everything else. The content checksum is turned on because Zstd leaves it off and a flipped byte otherwise decompresses cleanly to the wrong content; a decompression buffer is sized from the signed manifest and never from the frame, which is what stops a kilobyte declaring a gigabyte. Zstd vendored under BSD-3-Clause, legacy frame support off as attack surface we cannot need. `CDN.md` §5
- [x] cdn prepared-group cache and cancellation — `cdn::PreparedCache`, keyed by bundle root **and** dictionary hash because a group compressed against one dictionary is a different artefact from the same group compressed against another. LRU, bounded, thread-safe, and frames handed out as shared ownership so an eviction cannot free bytes underneath a client still streaming them. Cancellation is load-bearing: a cancelled request costs no compression, and one cancelled mid-preparation has its result discarded rather than delivered to nobody
- [x] cdn as a cache server — `CDNSettings` is the whole of an origin's setup, and CDN.md §6's three sources are field combinations rather than three programs: local store (`AllowUpstream` off), cache server (local first, forward on a miss, keep what came back) and pure proxy (`LocalFirst` off, `CacheUpstream` off). Local content is checked before anything external, which is what makes a hit cost no network at all. What an upstream returns is verified against the **signed** manifest before it is cached or served — a length check, honestly not chunk-level, because the chunk layout inside a group is not designed yet; the client verifies end to end regardless, so this is defence in depth. Upstream attempts are bounded, and an upstream that is down is counted apart from one serving wrong content
- [_] cdn wire streaming — parallel group streams over a real connection. **The blocker this line used to name is gone**: v0.3 built the loopback and asio UDP transports, so `net::Transport`, `Link`, framing, reliability and encryption are all in place. What is still missing is `net`'s `http/` sub-area, because a content origin serves bulk bytes over a request/response protocol rather than over a game datagram channel with a per-tick packet budget, and `mono.cdn` links `core`, `parallel` and `assets` — not `net` — so this also moves the origin's link row. Unblocked and unbuilt, which is a different state from blocked. `CDN.md` §5
- [x] cdn async pipeline — `cdn::Origin`: submit, pump, take, cancel. A publication is immutable and publishing is an **atomic swap**, so a request already admitted is served against what it was admitted against whatever is published underneath — pinned by a test that swaps mid-request. Concurrency is per request; `Jobs::For` appears in exactly one place, compressing a known set of groups, because that is CPU work with a known end and the pipeline around it waits on a filesystem. Cache lookups happen before the fan-out so a hit costs no compression. A bundle with no payload is refused rather than served empty. `CDN.md` §3
- [_] the client half of the async pipeline — a fetch issued from a world lives inside a tick, so its completion applies at the barrier; a chunk visible mid-tick is a desync. Belongs to `Engine::assets` and the world driver rather than to `mono.cdn`. Both of those now exist — `world::Driver` runs the barrier and `assets` is at L8 — so what remains is the `Ticket` shape v0.2 built for the buses applied to a fetch, and `assets` gaining a dependency it does not have today. `CDN.md` §3
