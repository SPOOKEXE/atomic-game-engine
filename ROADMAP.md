
# ROADMAP

## Editing

Do NOT add new deferred work as a roadmap item. Place it in
`docs/DEFERRED.md`. If a TODO item is not FULLY completed, split the
TODO item, keeping the concise short dash point list with block infront and
split it as another item under the same version.

For example, if we complete A and B but not C and D:
```
### v0.5
- [x] do: A1, A3, A5
- [_] do: A, B, C, D
- [x] do: G, H, I
- [x] do: K, K2, K3
```

becomes:
```
### v0.5
- [x] do: A1, A3, A5
- [x] do: A, B
- [x] do: G, H, I
- [x] do: K, K2, K3
- [_] do: C, D
- [_] deferred `D0001` for later.
```

or defer to another version.

### v0.15

- [x] rendering, physics and replication are unified under `mono.engine` — audited, and the verdict is that they already were. Three real faults found and fixed rather than a restructure: `mono.client` called `physics::RegisterCharacterSystems` while never naming `Engine::physics`, so the edge arrived transitively through `examples → script → physics` and nothing declared it; `client::CollectInstances` and `client::CollectReplicated` each wrote their own fourteen-member `DrawInstance` aggregate and had already drifted on which components they treat as optional, now both through `scene::MakeDrawInstance`; and `unified::Harness::DrawnPositionOf` re-derived a draw-list ordinal without the `Visible` skip its collector makes, so one hidden part anywhere ahead of the subject reported a different entity's position as a plain number
- [x] everything is components and not OOP under the hood — audited across every `mono.X`, and the pattern that keeps it that way is worth naming: a module needing a large private working set puts it in the ECS as a named `Store` resource and guards the storage with a `friend` struct in `src/` (`physics::PhysicsWorld`, `effects::ParticleSystem`, `replication::SnapshotBuffer`, the three `scene` catalogues). The one candidate raised — `Editor::ContentMeshFacts` — was examined and is **not** a violation: nothing reads that map but the editor, `script::ContentService` reads the per-world `scene::MeshCatalogue` the editor writes, and the map is what seeds a world opened after a mesh arrived. `input::Translator::Current` is a second `scene::InputState` by necessity, because there is one keyboard and N worlds

The argument for hiding it holds for a client replica, which is the one picture in the editor that is exactly what a player sees, and does not hold for an authored scene that happens to be running: `ShowGrid` is already the one-click answer for an author who wants the clean picture, so the mode does not need to decide it for them

- [_] the mirror bug: the half that is not a defect. Mirror-in-mirror-**in-mirror** still draws the inner panes as flat tint, and the cause is structural. **A pane drawn inside another surface's picture is sampled with a matrix fitted to the *eye*** — `drawMirrors` binds `shown.PreviousSampling`, which `AimSurfaceCameras` fitted to the viewer, so a pane appearing inside another's reflection is projected by a camera that is not the one looking at it, the coordinate leaves 0..1, and `opaque.frag` falls back to the plain lit pane. `Renderer.hpp` states the reason already: "a surface's camera is a function of the eye and cannot compose down a recursion, and a portal's has to." That is why `PortalView` is a separate recursive pass with a camera per level and mirrors were left on the flat one. Closing it means giving mirrors what portals have, which is render-graph-shaped work and belongs with the pipeline entries rather than ahead of them.
  - Reproduced by `examples/MirrorDepth.luau` — three panes chained, viewer turned 60 degrees. `client --script <stage>/assets/examples/MirrorDepth.luau --frames 200 --capture out.bmp`; the client hangs on *shutdown* rather than on render, so the capture is written first.

- [x] `Renderer::SetSurfaceBounces` has a caller at last. It shipped with a comment calling the knob public — "a scene built around a corridor of holes can ask for more" — and **nothing anywhere set it**, so every scene resolved exactly two levels of surface-seen-in-surface whatever it was built from. `studio --surface-bounces N` is the first caller it has ever had. Measured on `Mirrors`: two bounces against four differ by **2.17% of the frame against a 0.21% noise floor**, ten times the floor, so the depth limit was visibly costing that scene a layer

Sixteen repeats instead of four, and a third instead of six tenths: the gap the assertion measures gets **wider**, so the discrimination is stronger and the flake is gone. - [x] `D00114` closed, and not the way it was framed. The entry's headline case — `FindFirstChild` — is **still the union**, deliberately: resolving it to its receiver was the cheap option filed here, and it is simply wrong, because a child of a `Model` is not a `Model`. What was built instead is narrowing wherever the buffer *writes the class down* (`Instance.new`, `game:GetService`, the `OfClass`/`WhichIsA` pair, `:Clone()` carrying its receiver, and plain aliases, followed recursively), a fix for a real stale-fact bug where a local reassigned from something unreadable kept claiming the class of its first assignment, and — the part that answers the entry's actual warning — **every row now says which kind of list it is in**. - [x] `D00115` closed: a character's limbs no longer pay wire for transforms the receiver overwrites. Two of the entry's own assumptions were wrong — it needed no wire-format decision, because a delta already carries only changed rows so an omitted row is indistinguishable from an unchanged one; and it needed no new tag, because `scene.CharacterLimb` already *means* an entity whose frame is derived from its root. `Authority::SuppressWhenTagged` skips a slot's delta rows for tagged entities, the pairing lives on `ReplicatedComponent` so both hosts apply it, and the tag crosses the L12-to-L7 tier gap as a string, which is rule 4
- [x] mip chains — all three halves. `TextureData::Mips` holds levels 1..N *beside* the base rather than concatenated with it, because a dozen call sites check `Pixels` against `Width * Height * BytesPerPixel` and one flat buffer would make every one of them read a third too much while still compiling. Level dimensions are derived by `MipExtent` and never stored: a stored per-level size is the one field of a level an attacker gets to choose. VERSION 3, with v1 and v2 still read. Built by `bake::ResizeImage` through a new `NodeKind::Mipmap`, which `assetc` places immediately before the write.
- [x] **and the sampler was the actual bug.** `mipmap_mode` has said LINEAR since v0.8, but the zero-initialised `max_lod` clamped every fetch to level 0 — so a chain could have been built, serialised and uploaded and still never sampled, with three modules each looking correct on their own. `min_lod = 0`, `max_lod = 32`
- [x] **a flipbook's chain stops before its frames bleed**, and that decision mattered more than the code. Halving a grid is safe only while every destination pixel falls inside one cell, so the chain ends at the last exact halving of the cell size. Padding a gutter was rejected because it changes what a flipbook *is* — the `FlipbookSide` division lives in `render::FlipbookCellAt` and in every UV that samples a sheet — and refusing the texture outright was rejected because it throws away an image that was fine without a chain. Bleeding is the failure worth refusing precisely because it is invisible in the file and reads as the cell arithmetic being wrong
- [x] built-in textures have mip chains, and the tier argument that blocked them was the bug rather than the reason. `assets::ResizeImage`, `MipChainLevels` and `BuildMipChain` are pure arithmetic over `assets::TextureData` and reference nothing from `bake` — they sat at L9 only because `bake` happened to be the first caller, while `MipExtent` and `MipLevelCount` were already at L8. So the filter moved **down** to join them and `bake`'s copies were deleted rather than wrapped, which is the rule about two ways to do one job. `MakeChecker`, `render::DefaultTexture` and `render::MissingTexture` now build their own chains and upload seven levels through the path `TextureTable::Upload` already had. No new link edge, so `expected_graph.json` is untouched
- [x] the mip sampler and the multi-level upload are verified **on a device**, and by measurement rather than by a screenshot. `--verbose` only proves nothing complained, which cannot tell a sampled level from one clamped away — `max_lod` sat at zero for four versions while `mipmap_mode` said LINEAR, and no log line ever mentioned it.

The scene is static, so two captures of one build are **byte-identical** — a zero noise floor, and every digit of a difference is the change.

- [x] svg rendering support (and cdn) — a hand-written rasteriser in `bake`, no new vendor dependency, which is the house style every other decoder here follows. **Dispatched by name and not by a text sniff**: `ImageFormatOfName` is consulted only after `ImageFormatOfBytes` returns `Unknown`, because a `<svg`/`<?xml` prefix is a claim over all text and would capture the next XML-shaped format the module learns — and a `.svg` holding a PNG still decodes as a PNG. **The raster size is a node parameter**, `NodeKind::Rasterize` appended after `Write` since ordinals are on-wire, because an SVG has no intrinsic pixel size and a post-hoc `Resize` would be rasterising twice. `assetc` applies `--max-texture` by re-rasterising at the cap.
